# 主图载入在途时禁用跨图区，而不是把选择排队

**Status:** accepted（2026-09-30）

主图（重新）载入成功时，`AuditPage.vue` 会走 `setChartObservation` → `resetCrossImageSession`，把跨图会话连同**仍在飞行中的对照图请求**一起清掉（[任务 08](../../.scratch/stage-5-stability-submission/issues/08-cross-picker-cancelled-during-load.md) 的 CI trace 里表现为 `/api/audit/sample` 的对照图请求被中止）。用户在这段时间里选择对照图，会看到「选了下拉框又自己弹回去、且没有任何说明」。我们决定：**主图载入／读取在途期间，跨图区中会开始或改变配对的控件一律禁用，并在跨图区显示一行说明；载入结束（成功或失败）后立即恢复可用。** 这样用户是在动手之前就被告知，不会再出现「操作了却没有任何反馈」。

## 为什么不是「排队到载入完成后再执行」

排队的收益是「慢加载时跨图区仍可操作」，但要处理三个分支才能不自相矛盾：

1. **载入失败**：没有新的主图观察值可以配对。执行排队项会把对照图配到**旧**主图上（用户未必想要），丢弃排队项又回到「操作了没有任何说明」——正是本任务要消除的行为。要让失败分支也诚实，必须再加「排队中／载入失败，已忽略你刚才的选择」这类状态与提示。
2. **载入被取消**（换图、重新框选、取消读取）：同上，排队项要么落到旧主图上，要么被丢弃，都需要额外的说明状态。
3. **排队期间改选**：要定义后选覆盖先选、还是「第一条生效」，并让界面如实反映排队中的那一条。

而这段时间跨图区本来就没有可比较的对象：`setChartObservation` 会清空配对，`crossCurrentClaimId` 直到新观察值落地才有效。放开选择器买不到任何可用比较，只是把同一个失败模式提前到「排队」里。禁用方案把状态数从「载入中 × 排队中 × 失败／取消」压回「载入中」，语义最直白。

## 决策范围：禁用什么、不禁用什么

禁用（会开始或改变配对，或效果会被载入时的重置吞掉）：

- 「选择对照图」与「更换对照图」下拉框
- 「或上传一张」文件输入
- 「读取这张对照图」按钮（会发起 `/api/audit/image`）
- 「确认对照图读数」按钮（会发起 `/api/audit/check`，经 `beginReferenceRequest` 登记为在途请求）
- 「当前图主张」「对照图主张」两个下拉框，以及口径四要素的「确认一致」按钮（都只改会话内状态，会被 `resetCrossImageSession` 清掉）

不禁用：**「移除对照图」**。它的效果是「把对照图去掉」，载入成功后的重置也只会让它保持「已去掉」，不会被静默撤销，因此不构成「操作了却没有任何反馈」。这一点是刻意保留的，不要顺手改成禁用。

## 副作用与已知边界

- 慢加载时跨图区短暂只读。这一窗口与主图自身的等待窗口一致（预置样例本机几十毫秒、CI 上可达秒级；上传图的模型读取上限 45 秒），而在这段时间里主图本身也还不能核对——页面上「确认并计算」「读取整张图片」等按钮早已因为 `busyMessage` 处于禁用态，所以并不突兀。
- **仍然保留的既有语义**：用户**先**选了对照图（请求在途）、**再**主动切换主图，会连跨图会话一起被取消。这是「换主图即重置跨图会话」的既有行为（`resetCrossImageSession`），本次不改动；e2e 里「重置会取消仍在载入的对照图」继续守护它。
- 禁用状态只由「主图载入／读取是否在途」决定，不引入新的持久状态；载入失败、取消、换图、离开页面都会释放（`cancelImageRequest` 是唯一的释放点）。

## 语义落点

- 代码：`web/pages/AuditPage.vue` 的 `mainImageLoading`（在 `loadSample` 与 `analyzePendingUpload` 中置位，在 `cancelImageRequest` 与两个请求的 `finally` 中复位）与跨图区模板的 `:disabled`。
- 测试：`e2e/reader-workbench.spec.ts` 的两条用例（载入期间禁用并说明；载入失败后恢复可用且不残留半配对），三视口运行。
- 词汇：这是「对照图」在会话内的可用性约束，不新增领域术语，`CONTEXT.md` 不改。
