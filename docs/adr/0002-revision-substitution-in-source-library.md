# 资料库内既有发布的修订：程序做版本替代，不新增结论状态，也不实现「来源存在分歧」

**Status:** accepted（2026-10-01）

阶段四任务 06「固定资料库内的反证与版本复查」需要的第一件事是**可核对的来源对**。2026-10-01 的全量调研（[候选清单](../../.scratch/stage-4-source-audit/06-source-pairs-candidates.md)）结论是：**全国居民消费价格（CPI）口径下一对都没有**——「数据发布」历史列表 490 条里「修订／更正／订正／修正」只命中 1 条 GDP 修订公告，2026 年每份 CPI 发布页逐页检索无命中，基期轮换只有「2025 年指数按新基期重新计算、各月同比指数平均受影响约 0.06 个百分点」这句而没有月份级新旧值。唯一可用的一组是**非 CPI**的：社会消费品零售总额**环比增速**，三份发布都带官方修订声明，同一月份确实存在 2—3 个不同官方值。用户 2026-09-30 批准把资料库扩到该指标。

## 决策

1. **只实现「版本修订／版本替代」半支。** 当一条主张所引的发布**已被同系列后续发布按官方声明修订**时，程序用**修订后的值**作为对照基准，并在结论上附一条「版本复查」记录（修订前后值、官方声明的逐字原句、两份发布的标题／日期／链接）。
2. **不新增第六类结论状态。** 仍然只有「与来源一致／与来源不一致／来源待核对／推断依据不足／不支持核验」五类；复查记录是结论的**附加字段**，不是新状态。理由：新增状态要连带改建议生成、限定语、评测不变量与历史展示的每个分支，收益只是把「不一致」换个名字；而读者真正需要的信息是「官方后来把 0.35% 改成 0.40%」，这件事用附加记录说更清楚。
3. **「同口径冲突无法消解 → 来源存在分歧」本轮不实现**：没有任何可核对的分歧材料（CPI 无同口径冲突对，社零是明确修订而非分歧）。按仓库纪律，没有实测支撑的能力不写进声明；该分支留在 issue 06 的未完成勾选项里。
4. **资料模型**：`SourceMeasure` 增加可选 `period`（多月份发布里逐行的月份，缺省沿用 `document.basis.period`）；`SourceDocument` 增加可选 `revision`（官方修订声明原句、修订日期、被修订发布的 id）。**指纹只在新字段存在时才把它拼进规范化串**，因此现有三条材料的指纹不变、`frozen.libraryFingerprints` 无需改动；新增材料另行冻结。
5. **复查由程序在结论阶段完成**，不新增工具、不改调查预算（每轮 3 次／总计 6 次／4 轮／150 秒），也不让模型自行判定「这是修订版」——修订关系必须依据资料里的官方声明字段，这正是「模型提议、程序把关」在资料层的同一条规则。检索结果载荷会把修订信息一并给模型，让它的汇总能如实转述。
6. **模型提示词不改**：改动提示词会扰动已冻结题集的 20 题结果。程序侧的版本替代是确定性的，模型不需要知道它。

## 副作用与边界

- **资料库范围从「CPI」扩到「CPI + 社会消费品零售总额（仅环比修订序列）」**：README 的「产品边界」、报告 1.4／6.4／7.1、演示脚本的素材纪律都要同步；题集新增该场景的题并重新冻结，原有 20 题的哈希守护不变。
- **口径仍然是「对齐才可比」**：社零是另一个指标，**不能**用来核 CPI 主张；`evaluateApplicability` 的指标匹配不会因为它在库里而放宽。
- **修订幅度是 0.01—0.10 个百分点量级**，属「季节调整模型自动修正」，与 CPI 基期轮换不是同一件事，不能混用。
- **「额外耗时」如实记录**：程序侧替代 ≈0 ms，评测里按实际测量值写，不编造收益。
- 已发布值的修订只允许用**官方声明**解释；`data.stats.gov.cn` 月度库（唯一可能给出新基期数值的地方）本机被 WAF 403，未覆盖，见调研文件的「未覆盖的检索路径」。

## 备选方案与否决理由

- **新增「来源存在分歧」状态**：无材料可验，且会把五类结论的连锁分支全部扩大一遍。
- **让模型用一次追加检索自行发现修订**：多花一次调用、结果不确定，而且「是不是修订关系」不能由模型判定（仓库纪律：修订须有官方声明依据）。
- **把社零月度值拆成多份「资料」**：会让同一 URL 出现多条资料、并在检索里表现为两份同口径不同值，看起来像「同口径冲突」，与事实（官方声明修订）不符。
