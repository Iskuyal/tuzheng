# Anthropic Messages 协议支持与在线探测（2026-09-28）

在 Edge 实机走查模型设置页：旧版扁平设置文件（commandcode 网关，模型 `deepseek/deepseek-v4.1-flash`）读取时自动迁移为按协议结构；切换「接口协议」到 Anthropic Messages 后带出该协议的地址（`https://api.anthropic.com/v1`）与模型占位、地址说明改为「服务端会自行调用 `/messages`」、协议徽标与测试说明同步更新；Anthropic 无密钥时点「测试连接」返回「请填写 API Key，或先保存密钥后再测试连接。」，没有误用另一协议已保存的密钥。切回 Responses 保存后，设置文件重写为 `{activeProvider, providers}` 结构，原密钥保留（长度不变），页面与读取接口都不回显密钥；320px 与 390px 视口无横向溢出。

**Anthropic 协议在线探测（重点结论）：**用本机已保存的网关密钥请求 `https://api.commandcode.ai/provider/v1/messages`。该路由存在、鉴权头被接受，并且**只服务 Claude 模型**：所有非 Claude 模型（deepseek、gpt、glm、kimi 等族）都被网关以 `400 Model "..." is not supported on this endpoint. Use /provider/v1/chat/completions for OpenAI and OSS models.` 拒绝——该网关的 Anthropic 接口不能承载其他模型，非 Claude 模型要走 Responses／Chat Completions 面。Claude 模型（`claude-sonnet-4-6`、`claude-opus-5` 等）被识别，但当前套餐未包含：`403 MODEL_NOT_IN_PLAN: Claude Sonnet 4.6 available in Pro and above plans or extra on demand usage`，被应用正确归类为鉴权／权限失败。因此成功的在线连接测试与在线图片读取仍需在具备 Claude 权限（Pro 及以上套餐或按量付费）的端点或密钥上补做。诊断过程中另发现：Anthropic 卡曾保存一把与可用密钥不同的值（长度 112 位，可用密钥为 92 位），用它请求任何端点都返回 401 `Invalid 'Authorization' header or token`；密钥与卡片必须一一对应。

**附带发现与修复（Responses 在线路径，非本次新增能力）：**2026-09-28 实测发现两点上游行为变化。其一，网关对未知字段返回 400（`json: unknown field "verbosity"`），视觉请求中的 `text.verbosity: "low"` 已移除。其二，连接测试 64 输出上限被模型的思考 token 吃光（`status: incomplete`、`reasoning_tokens: 64`、空输出），上限调整为 512 后真实连接测试成功（模型 `deepseek/deepseek-v4.1-flash`，3.5 秒）。修复后真实读取复验：`consistent.png` 返回 1 条主张（标题 25%、80→100），耗时 29.5 秒、输出 3,237 tokens；`conflict.png` 连续两次被结构校验拒绝，原因是模型把 `claimedGrowthPercent` 返回为字符串 `"40%"`（期望 number）。模型当前还表现出：单主张读取耗时从 09-26 的 3.2—4.4 秒升至约 30 秒，多主张样例（`multi-claims.png`）在 45 秒超时内未完成。这些是端点/模型行为变化，应用按设计拒绝不可用输出，未做数值猜测。

**协议 vs 端点的边界补充（2026-09-28 查证）：**Anthropic Messages 是线格式而非模型绑定——多个厂商提供 Anthropic 兼容端点供 harness 使用非 Claude 模型（如 DeepSeek 官方 `https://api.deepseek.com/anthropic`、Kimi `https://api.kimi.com/coding/`、DeepInfra `https://api.deepinfra.com/anthropic`，以及自建 LiteLLM 代理在 `/v1/messages` 上做格式转换）。本项目 Anthropic 卡片同样不绑定 Claude：把这类端点填到版本段（如 `https://api.deepseek.com/anthropic/v1`）即可，模型名按其支持填写。commandcode 不支持这种用法——其 `/messages` 只服务自家 Claude 模型，探测过的其他 Anthropic 路径（`/v1/messages`、`/anthropic/v1/messages` 等）均 404，这是该网关的路由策略而非协议限制。

**DeepSeek 官方 Anthropic 端点在线验收（2026-09-28，团队提供的真实密钥）：**配置 `https://api.deepseek.com/anthropic/v1` + `deepseek-flash`（V4.1-Flash，`/models` 标注 `input_modalities: ["text","image"]`）后，应用自身的「测试连接」返回成功（644 毫秒）；经 `/api/audit/image` 真实读取自制样例：`conflict.png` 1.2 秒返回「年营业收入增长 40%」、80/100；`consistent.png` 首次因模型返回不符合结构被应用拒绝（`INVALID_MODEL_OUTPUT`），重试 1.3 秒成功返回「年营业收入增长 25%」、80/100。模型偶尔输出结构不符属已知波动，应用按设计不猜测、按重试路径恢复。**关键兼容发现：**DeepSeek 默认开启思考，思考模式与强制工具调用互斥（`400 Thinking mode does not support this tool_choice`）；应用在 Anthropic 请求中显式 `thinking: {"type":"disabled"}`（本次修复）后，连接测试与图片读取都通过。另：`deepseek-v4-flash` 是纯文本型号，传图片会被 400 拒绝，预设因此只收录多模态型号。

**各家 Anthropic 兼容端点检索结果（2026-09-28）：**DeepSeek 官方 `https://api.deepseek.com/anthropic`（客户端追加 `/v1/messages`，本应用填到 `/anthropic/v1`；官方 Responses 端点 `https://api.deepseek.com/v1/responses` 同期探测返回 200）；阿里云百炼 `https://dashscope.aliyuncs.com/apps/anthropic`（官方要求填到 `/apps/anthropic`，`qwen3.8-flash` 官方文档标注输入模态含图片、支持 Function Calling）；智谱开放平台 `https://open.bigmodel.cn/api/anthropic`（Claude 兼容；`glm-5.3-flash` 为 GLM-5 系列首个原生多模态）；OpenCode Zen `https://opencode.ai/zen/v1`（同时提供 `/messages`、`/responses`）；OpenRouter `https://openrouter.ai/api/v1`（原生 Messages 与 Responses，模型元数据标注图片输入与工具支持）；Anthropic 官方 `https://api.anthropic.com/v1`；commandcode 网关 `/messages` 仅 Claude 且受套餐限制；Kimi 的视觉支持只在 OpenAI 兼容端点（`api.moonshot.cn/v1`）有文档，其 Anthropic 兼容端点（`api.kimi.com/coding`）未注明视觉，暂不收录。**2026-10-02 已推翻**：官方《Model Configuration》写明「Kimi Code API supports both OpenAI and Anthropic protocols」、Anthropic 兼容 base 为 `https://api.kimi.com/coding/`，型号表把 `k3` 的多模态输入标为「Image, video」，已按「未鉴权对照探测 + 官方原句」补进预设 `kimi-coding-anthropic-k3`（仍是 `documented`、未做真实调用）；逐条证据见 [`.scratch/model-presets-research/endpoints-2026-10-01.md`](../../.scratch/model-presets-research/endpoints-2026-10-01.md) 的 2026-10-02 收口一节。

**工具调用兼容（2026-09-28 补充实测）：**`thinking: {"type":"disabled"}` 只能用于可关闭思考的提供方；GLM-5.3-Flash 官方文档明确「思考不可关闭」且不支持强制工具选择。应用因此改为两段式请求：先「关闭思考 + 强制工具调用」（DeepSeek、Anthropic 等），被 400 拒绝时回退「不带思考字段 + 自动工具选择」再试一次（仅 400 触发一次重试，其他错误直接抛出）。改动后 DeepSeek 路径重跑真机复验通过：连接 653 毫秒、`conflict.png` 约 1.1 秒读取「40%／80→100」。
