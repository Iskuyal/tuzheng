## 一、这条路径要证明什么

不是证明系统能判断配文真假，而是证明：**数字正确不等于整句成立——系统能指出一句配文里的哪一部分现有证据推不出来，并且不把「缺依据」自动当成「假」。**

1. 主张分三类：直接陈述、可检查推断、观点；观点标为「不支持核验」，不做真假结论。
2. 推断按部位核对：数值与口径、推断结论分别给「来源支持／来源矛盾／推断依据不足」，并说明缺哪一项依据才能继续。
3. 同一条推断，在**没有适用环比来源**时给「推断依据不足」，在**有适用环比来源**时按来源改判（方向一致即支持，方向相反即矛盾）。
4. 单次最多核验三条主张：超出与未展开的内容按原文列出并给出覆盖度提示，不静默丢弃。
5. 主张原文必须能追溯到图或配文的原文；配文只写月份时按图上标注补全年份。
6. 未达标就如实记录并缩小声明，不删题、不把替身或预置结果计入真实模型成绩。

**未展开与覆盖。** C/D/E 三轮里，模型声明过未展开内容的运行各占三分之一以上（有检索臂 15／15／17 次）；程序一律把它们逐条保留原文，没有一次静默丢弃。E 轮（与提交代码一致）起，声明按出处归类：能追溯到配文的记为「配文未展开」，其余（多数是图上说明、页脚、单位行）单列为「图上说明／其他声明」并**不计入配文覆盖**——E 轮有检索臂里约 66 条声明属于后者，配文漏项只有 3 条，若不分类会把图表页脚误报成用户配文里没核验的内容。程序按覆盖度发现的漏项另有提示（C 轮 4 次、E 轮 3 次「配文里…没有被已核验主张覆盖」）。q16 在三轮里都出现了明确提示，没有一次是静默丢弃。

## 六、收掉 02 的两个口子

1. **主张归属**。02 出现过「把检索到的官方原句当成一条配文主张并判与来源一致」。现在配文主张必须能在配文原文里找到（文字重合度下限，且主张里的数字必须出现在配文或图上），图内主张必须提供图上抄录且比较方向写在抄录里，否则降级为「来源待核对」并说明原因。**本轮五轮里没有再出现该类错误，规则本身由单元测试与 API 替身测试覆盖；但真实运行中没有命中过这类主张，所以不能宣称已经在线拦下过一次真实的归属错误。**
2. **配文缺年份**。02 有检索臂有 4 次运行因为「配文只写 12 月、模型不去图上取年份」而判错。现在程序按图上标注的月份补全年份（图上有多个年份或没有年份时不猜，保留原样并说明）。修复后 q01、q02、q10 在后三轮的有检索臂合起来 **18/18 通过**（C 轮 q01 无有效运行，另两题全对），记录里配文主张的月份都落到了 `YYYY-MM`。补全说明写在结论里（`periodNote`），C/D/E 三轮的逐次记录早于该字段加入，这几轮看不到补全说明，但月份已经补全。

会话末尾复现到确切原因：提供方返回 **`402 {"error":{"message":"Insufficient Balance"}}`** ——本机 API 余额在整轮评测期间被耗尽，E 轮后半段的失败大多属于这一原因。E 轮完成于余额耗尽前后，因此它的无检索臂只有 24 次有效运行，20.8% 这个数字波动区间很大，不外推。

仍在的缺口：A—D 轮的失败只记到了 `upstream`／`HTTP 400`，当时没有保存响应正文（正文捕获是在 E 轮开始后才加上的），所以**这些 400 的上游原因未经验证**，不能断定是余额、限流还是请求形态问题。这项留给下一次有余额的复跑。

## 九、不能外推、尚未验证的部分

- 17 道题全部是开发题，**没有预留题**；五轮里没有人先调好再考的留出题，样本量也不足以给出通用准确率。
- 只验证了 `deepseek-flash` + Anthropic Messages 协议；Responses 协议的工具循环仍只有替身测试。
- 上游失败率 25%—50% 且原因未完全定位（见第七节）；E 轮受余额耗尽影响，有效样本最小。
- 主张分类的正确率没有单独统计（题集只在 q15 用 `kind` 固定了「观点」一类），分类错误会以状态错误的形式体现，不能从本记录读出分类准确率。
- 模型仍会把图上说明文字写进 `omittedClaims`（程序已按出处分开计，不再计入配文覆盖），也会漏报图内主张（同一张图拆 1—3 条，条数在运行间跳动）。
- 术语类主张（q12）只能到「来源待核对」或「推断依据不足」：结论词汇不表达「与术语页矛盾」，这是 02 就记录、本轮仍未解决的能力边界。
- 「配文缺年份 → 从图上补全」这条由程序与单测覆盖；本轮记录里没有单独的补全说明字段（字段是 E 轮之后加的），因此只能从月份取值判断已补全。
