# 目标读者任务验证：执行包

准备日期：2026-10-07。材料已准备，**尚无真实参与者或用户收益结果**。邀请5—8位只有截图、没有原始数据的普通读者；招募、知情同意及任何收费调用由负责人安排。匿名P01—P08是待招募槽位。

执行材料：[参与者任务](participant-tasks.md)、[主持人指引与独立答案](facilitator.md)、[匿名记录模板](records-template.json)。主持人答案不得给参与者，也不进入模型请求。

1. 记录参与者同意与目标用户资格；姓名、联系方式和编号对照留在仓库之外。
2. 选定产品代码与模型配置，记录候选锁哈希。先用 [预检入口](../../evaluations/candidate-runbook.md) 核对。
3. 奇数编号先手工做A组，再用产品做B组；偶数编号先用产品做A组，再手工做B组。每组T1—T4，两组之间不告知标准答案。输入难度相近只是设计假设，首次试测后如改题，要保存旧方案并另开轮次。
4. 手工条件同样提供任务中列出的来源摘录和链接，允许纸笔及计算器。产品条件按参与者任务操作；主持人不能替参与者作判断。
5. 从看到任务到给出最终回答计时，失败、超时及放弃也入表。每题建议最多5分钟；记录真实用时和中性提示次数。无记录则保持null，不能补为0。
6. 5位即可形成描述性小样本；未招募的槽位保持pending。完成后用下述命令统计，不输出统计显著性、普遍提效或付费需求结论。

```powershell
npm run study:readers -- --template .cache/reader-study/新轮次.json
npm run study:readers -- --report .cache/reader-study/已填写轮次.json
```

模板预分配8人×4任务×2条件=64条，不能删掉未完成或失败行；脚本核对交叉安排、同意、逐人原答和观察依据。填写state、execution、seconds、hints等字段，详见主持人指引。原始记录不含姓名、电话或密钥。统计输出分别列手工、产品、真实在线产品、离线产品与证据卡；时间配对附操作类型，不混成一个效率数字。

T1使用预置图内样例可离线操作。T2—T4来源核验需要真实模型；**本包不授权收费调用**。若尚未获批，可先让参与者阅读原图、资料卡和既有明确标注的证据卡，记录execution=`evidence-card`，只验证理解，不称为产品流程成功。不得用替身响应冒充真人操作实时模型的证据。T4离线卡片按先缺口、后用户回答、再来源判断三张卡顺序揭示；最终答题前不揭示主持人答案。

后续编辑访谈只记录假设：最近一次核稿/看图经历、发生频率、当前方法、实际错误成本、下次是否愿意使用及约定的实际复访。不以“喜欢”“愿意付费”替代真实使用或支付记录。
