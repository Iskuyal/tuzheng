# 主持人指引与独立答案（不发给参与者）

本文件提供答案和主持流程，不含实测结果。先打开 [参与者任务](participant-tasks.md)，确认图片能打开、参与者不知道标准答案，再按 [执行顺序](README.md) 分配任务。记录阅读、操作、回答及失败恢复的实际过程。

开场：“我们在测试材料和工具，不是在考你。请按自己的理解完成任务；看不懂或不能判断都可以说出来。随时可以退出。请不要提供姓名、联系方式或其他私人信息。”取得同意后将consent与eligible设true；eligible指符合只有截图的普通读者目标。

每题只读任务原句，启动计时。参与者卡住时先等，再最多用“你可以告诉我现在卡在哪一步”“请按你看到的信息继续”“如果不能判断，也可以说明还缺什么”等中性提示；每次计hints。不要说“算一下百分比”“看环比”“点这个按钮”。帮助操作与帮助判断分别写在evidence字段，成功也记录帮助。

数值答案来自算式及仓库固定资料：`stats-cpi-2025-12`、`stats-cpi-2026-08`。A组T3的全国城市与全国不同；B组T3的四月未覆盖。没有必要，也不允许修改生产题集/预留题期望来配合这份研究；本包不使用holdout-v1题图，以免在独立评测前消费预留输入。

T4补充卡只在追问指向正确目标和字段后给出，主持人不能用补充卡纠正错误追问。未追问、问错对象、失败或超时均如实记录；手动给出答案后才得到正确状态，不能算完整路径成功。离线证据卡按相同顺序展示，记录evidence-card；成功只说明参与者理解了材料。

## 填写约定

- `pending`：尚未测试，所有数值/布尔结果与execution保持null，response/evidence/failureReason为空。
- `completed`：确实完成一次尝试，填success真或假、seconds、hints、原答response与观察依据evidence。答错也可记completed且success=false，不应从统计删除。
- `failed`／`abandoned`：success=false，写实际失败或退出原因；有计时就填，没有则null。仍在已尝试分母中。
- `execution`：手工为manual；实际预置产品为offline-product；真实模型产品为live-product；只读证据卡为evidence-card。A/B正式对比不得用替代输入悄悄更换。
- `misjudged`：是否对可判断的主张作错判断；`evidenceExplained`：是否能指出适用的依据；`pendingUnderstood`：是否理解待核对含义。不适用/没观察保持null，不能默认为false。
- 每题计时止于最终回答或停止，不排除读取、等待及失败恢复。记录模型失败不等于读者不会操作：failureReason写清上游故障、输入错误、误解或自行退出。
- 模型运行ID或明确的离线材料版本写入evidence。录屏仅在额外同意后由团队保存，仓库只留脱敏文字。

统计同时看成功数/实际尝试数、全部计划数、失败、未测、提示、误判、能否指出依据和待核对理解；时间列中位数与缺失数。逐人逐题配对差值为产品用时减手工用时，负值表示该对用时较少；先核对输入与execution可比性，再解读。不能用成功题子集概括所有任务，也不输出小样本普遍提效结论。

试测后的访谈可问：最近何时遇到类似图、当时怎么查、最难步骤是什么、是否在实际核稿中复用、愿不愿意约下一次真实任务。关于长期价值与付费仍是待验证假设。
