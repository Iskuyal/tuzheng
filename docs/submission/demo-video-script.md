# 演示视频脚本、分镜与逐条走查清单

**状态（2026-09-30）：脚本就绪，视频待团队人工录制。** 仓库内的材料（本脚本、技术 PDF、README、截图）已按阶段四 01—05 的验收范围冻结；
视频录制**必须由人在有 GUI 的机器上操作**（电脑截屏或 OBS），录制前请先按第 1 节与第 4 节在真机 `npm run dev` 上把演示题实际跑通。

- 目标时长 7:00 左右（允许 5:00—8:00），**至少 1080p**，输出 MP4，普通话讲解。
- 只展示已验收能力；未验收项（固定库内反证与版本复查、公网演示、Responses 协议工具循环）**不出现在视频里**。
- 素材纪律：视频里的每一段模型输出都必须是**现场真实调用**。可以演示失败，不可以把替身响应、预置动画或预置观察当成本次实时结果；录制时若某题出现漂移，按第 3 节的替补方案处理，不要剪成「每次都成功」。

## 1. 录制前准备（人工，约 20 分钟）

1. **环境与进程**
   - `git pull` 取到本任务提交；确认工作区干净。
   - 先清掉可能残留的开发进程（反复 `npm run dev` 会累积孤儿进程，占用 3001／5173 端口会让页面报错）：
     ```powershell
     netstat -ano | findstr ":3001 :5173"     # 有 LISTENING 就记下 PID
     taskkill /F /PID <PID>
     ```
   - `npm install` 后 `npm run dev`，确认 <http://127.0.0.1:5173> 可打开，`http://127.0.0.1:3001/api/samples` 返回 200。
2. **模型配置**：设置页 →「接口协议」选 **Anthropic Messages** → 地址 `https://api.deepseek.com/anthropic/v1` → 模型 `deepseek-flash` → 填入 Key → 保存 → 点「测试连接」确认成功（约 1 秒）。**截图/录像里出现的密钥输入框要提前填好，录制时不要再输入密钥字符。**
3. **费用**：本片约 10—15 次真实请求（含重试），按实测单价不到 0.2 元。开跑整组评测不是本片内容，**不要跑 `npm run eval:source-audit` 整组**。
4. **窗口与画面**
   - 浏览器用 Edge，窗口宽度 1280—1440，页面缩放 100%；系统缩放保持 100%（否则 1080p 下文字发虚）。
   - 录制分辨率 **1920×1080**（OBS：基础分辨率与输出分辨率都设 1920×1080，30 fps 足够，码率 6000—8000 kbps；或使用 Windows 自带「Xbox Game Bar / 截图工具录屏」并把窗口最大化到 1080p）。
   - 关闭通知（Windows 专注助手），关闭无关标签页与聊天窗口；任务栏隐藏或放到底部。
   - 提前把三个要用的图片文件放到桌面快捷方式，录制时用文件选择器选取：
     `web/public/samples/conflict.png`、`cpi-2025-12.png`、`cpi-2026-07-08-yoy-trend.png`、`cpi-2025-12-yoy.png`。
5. **脚本与提词**：把第 3 节的分镜表打印或用副屏打开；旁白是「要点」不是逐字稿，按自己的话说更自然，但**数字与结论措辞必须与屏幕一致**。
6. **提前声明**：视频开头用一句话说明「本片不涉及数据的真实性判断，只核对配文与图示、与所引公开来源是否一致」。

## 3. 分镜表（时间轴）

> 「必须可见」列是这一段的验收点：录制后逐条核对。方括号里是替补方案。

### 0:00—0:30　开场
- **画面**：技术报告封面页或 README 首屏，慢慢滚到项目一句话。
- **旁白**：产品叫什么、给谁用（只有截图的普通读者）、解决什么问题；一句话说明本片会演示「图内自检 → 配文与公开来源核对 → 修改建议」三段，并声明后面所有模型输出都是现场真实调用。
- **必须可见**：作品名；「团队自制样例」字样（说明素材来源）。

### 0:30—1:45　图内闭环：原图 → 模型观察 → 人工确认 → 程序计算
1. 打开 `/audit`，上传 `conflict.png`（左侧显示原图缩略与放大按钮）。
2. 点「读取整张图片」，**等待真实模型返回**（1—3 秒），展开「本次读取过程」面板。
3. 旁白要点：模型只负责读——它返回的是图上原文与数值，**不返回计算结果、不返回结论**；面板里可以看到模型名、耗时与 token。
4. 逐条确认读数（2024 年 80、2025 年 100），点「确认并计算此主张」。
5. 结论卡出现：公式 `(100 − 80) / 80 × 100 = 25.00%`，标题写 40%，判「图内矛盾」。
- **必须可见**：原图、模型观察面板（模型名／耗时／原文摘录／数值）、人工确认动作、程序公式与「图内矛盾」结论。
- **旁白必须说清**：计算与判定由程序完成，模型读错时用户可以先更正再计算。
- [若读取失败或超时：如实说明这是上游失败，重试一次；仍失败则改用「多主张样例」并说明该段用的是**预置示例值**（不能说是模型读取）。]

### 1:45—3:35　来源核验主路径：主张拆解 → 工具检索 → 逐条结论
1. 打开 `/source-audit`，点「载入团队自制 CPI 样例」，配文自动为「比上月上涨 0.8%」，点「运行来源核验」。
2. 结果区先看运行摘要（模型、耗时、轮数、工具调用 n/6、tokens）与停止原因。
3. 配文主张卡：展开「依据、推断缺口与未解决项」——指标／范围／月份／数值／比较方式，原文核对（配文原文可追溯），结论「与来源不一致」，依据原句引用官方发布里的环比 0.2%，相差 0.6 个百分点。
4. 图内观察卡：图上没写比较方式 ⇒ 「来源待核对」，并说明缺哪一项才能继续。
5. 「引用与检索命中」：官方发布带原始链接、发布机构、发布日期、摘录与指纹，标注「用作数值依据」；下方「本次排除的材料及原因」列出 2026-08 干扰项（月份不符）与术语解释页（不能作数值依据）。
6. 「工具轨迹」：逐条看第 1 轮检索、第 2 轮比较数值、以及一条**未执行**的调用（超出本轮上限，程序拒绝并留原因）。
- **必须可见**：主张卡的分部位结论、引用原始链接与发布机构、「依据原句」摘录、被排除材料的原因、轨迹里的拒绝条目。
- **旁白必须说清**：检索命中的材料必须通过口径匹配才能当数值依据；程序校验工具名、参数与调用次数。

### 3:35—4:30　推断检查：数字对得上 ≠ 整句成立
1. 换成 `cpi-2026-07-08-yoy-trend.png`，配文填「8 月 CPI 比上月便宜。」，运行。
2. 展开结论：图上只有同比、没有环比；资料库 2026-08 发布记载**环比上涨 0.4%**，与「便宜」方向相反 ⇒ 「与来源不一致」；分部位显示「推断结论：来源矛盾」。
3. 旁白要点：同一条推断，在没有适用来源时会判「推断依据不足」，并明确写「不代表结论为假」；有来源时按方向改判。
- **必须可见**：分部位（数字与口径／推断结论）结论、「与来源不一致」、判断依据的官方原句。
- [若这次运行没有拆出这条推断或状态不符：重跑一次并说明模型行为有漂移；仍不符则跳过本段，在旁白里说明该题在开发评测里的表现与局限。]

### 4:30—5:30　必要补证：回答不了的问题交给用户
1. 换成 `cpi-2025-12-yoy.png`，配文填「12 月 CPI 上涨 0.8%。」，运行。
2. 出现「模型请求确认」：问题指明影响哪条主张、缺的是比较方式，并声明回答只用于确定口径。
3. 输入「同比」，点「提交补充并恢复调查」；等待恢复段返回。
4. 看「补证记录」（用户提供、解析为 year-on-year）与「结论变化」（同一条主张 before → after 与原因）；建议配文从带「（暂未核实）」变为保留原句。
- **必须可见**：追问文本与「影响的主张」、补证记录里的「用户提供」标注、结论变化对照、建议随之变化。
- **旁白必须说清**：补充只用于确定口径，不是官方来源；恢复沿同一条调查记录续跑，预算不重置。
- [本段稳定性说明：q18 追问率有漂移（04 轮 3/3、05 轮 2/3）。若这次没有追问，点「重新核验」再跑一次；两次都不追问，就改演示 q20 的单段建议（在旁白里如实说明该题曾出现未追问的运行）。]

### 5:30—6:20　修改建议：采用与撤回
1. 用 `cpi-2025-12-yoy.png`，配文填 `2025 年 12 月 CPI 同比上涨 0.2%，2026 年 5 月 CPI 比上月上涨 0.1%。`，运行。
2. 「修改建议（不自动替换原配文）」：两处改动逐处展开——第一处「替换数值」改成 0.8%（引用官方发布）；第二处「保留并限定／建议删除」，理由是资料库没有 2026 年 5 月发布。指出每处都标明「模型提议（已通过程序校验）」或「程序按结论生成」。
3. 若出现「模型提议但未通过校验（不采用）」区块，放大并念一条拒绝原因（这是真实运行的自然产物，不要为它重跑）。
4. 点「采用这条建议（写入配文输入框）」：配文输入框被改写，提示需要重新核验，原结论与建议进入「历史结论（仅作历史展示）」——展开历史条目，指出其中标注「已采用建议」与依据快照指纹。
5. 再手动改一个字（例如在配文末尾加一个句号）并指出：输入一变，旧结论与旧建议立即失效、只作历史展示，**不会**被迟到响应复活。
- **必须可见**：逐处改动的原句／建议／理由／引用、生成者标注、采用动作、历史条目与「不代表当前结果」文案、改动即失效。
- **旁白必须说清**：建议不自动替换；采用是用户动作；历史结论不代表当前结果。

### 6:20—7:00　失败恢复：错误要说人话
1. 到设置页，**故意**把地址改成不可用的根地址（例如 `https://api.deepseek.com/anthropic/v2`），保存。旁白先说明「这是故意改错，用来演示上游不可用时的表现」。
2. 回到 `/source-audit`，载入样例 → 运行：页面只显示失败原因，结果区、轨迹、停止原因**全部不出现**（旁白强调：失败时不展示任何结论，也不用上一次的结果顶替）。
3. 顺便演示另一种降级：把地址改回正确值之前，指出「未配置密钥」会出现直达设置页的链接（可跳过，避免清空已保存的密钥）。
4. 设置页改回 `https://api.deepseek.com/anthropic/v1` 并保存，回页面重跑一次 → 正常出结论。
- **必须可见**：错误提示文案、无结论区、恢复后正常结果。
- [如果不想改动真实配置：改为在录制前把 Key 临时改错一位，演示「鉴权失败」后再改回；同样要在旁白里说明是故意改错。]
