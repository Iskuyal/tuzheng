# 模型配置：本机文件与服务端环境

2026-10-02 经用户授权调整密钥约定：默认本机配置，显式启用时允许服务端环境变量。两种模式使用同一配置源选择入口 `createModelSettingsStore`，整份选择协议、地址、模型、密钥，不逐字段混用。

## file（默认）

`MODEL_CONFIG_SOURCE` 未设置、留空或为 `file` 时，使用 `%LOCALAPPDATA%\TuZheng\settings.json`。设置页编辑两种协议各自的配置，支持保存、留空保留密钥、清除密钥、旧文件迁移和损坏文件重建。其余 `MODEL_*` 环境字段全部忽略。文件缺失时保留原有示例地址／模型和未配置密钥的行为。

## env（显式启用）

在启动服务的环境中设置以下五项，根目录 [.env.example](../.env.example) 只给出空值与说明。优先使用运行进程／服务管理器注入；使用本机 `.env` 时，该文件是部署者提供的输入，已被 Git 忽略，应用不会将密钥写入或写回任何文件。修改后需重启服务。

| 变量 | 含义 |
| --- | --- |
| `MODEL_CONFIG_SOURCE` | 必须显式为 `env` |
| `MODEL_PROVIDER` | `openai-responses` 或 `anthropic`；这是协议标识，兼容服务商也使用对应协议标识 |
| `MODEL_BASE_URL` | 服务根地址（如 `https://api.example.com/v1`），不能填写完整调用端点 |
| `MODEL_NAME` | 当前协议支持的模型名，非空且最长 120 字符；读图需模型支持图片输入 |
| `MODEL_API_KEY` | 非空且最长 1000 字符，只在服务端内存中使用 |

服务端在创建配置源时对四个模型字段取一次快照并去除首尾空白。字段缺失／空白、非法协议、超长字段或非法地址会返回 `INVALID_ENV_SETTINGS`（503），设置页显示具体规则和只读来源；不会用文件或默认值补齐。非法来源选择器直接使启动失败，错误只显示允许的值。未启用协议保持空配置，不能在页面切换到另一套设置。

地址与文件模式共用校验：远程必须 HTTPS；HTTP 只允许真实回环 IP、`localhost` 或 `.localhost` 地址。拒绝伪装 `127` 前缀的域名，拒绝 URL 用户名／密码、查询参数、片段以及完整 `/responses`、`/messages`、`/chat/completions`、`/completions` 路径。

环境模式下设置页显示协议、地址、模型和 `hasApiKey` 状态，密码框始终为空；协议、预设、地址、模型、密钥与保存按钮均禁用，不提供清除密钥入口。直接 `PUT /api/settings` 返回 `SETTINGS_READ_ONLY`（409）。手动连接测试只提交空对象 `{}` 并使用整份环境配置；带任何表单覆盖的请求被拒绝（400）。**连接测试会调用模型并可能产生费用，不会自动执行；本次验收全部用替身，0 次真实模型调用。**

## 消费入口与安全边界

- `GET/PUT /api/settings` 与 `/api/settings/test-connection` 使用同一配置源。
- `/api/audit/image`（主图和对照图共用）与 `/api/source-audit/investigate` 按完整配置选择适配器；`resume` 复用初查驱动器和内存会话。修改环境后重启会清空会话，旧会话不会切换到另一配置继续调用。
- `npm run eval:source-audit` 同样加载根目录 `.env` 并使用该选择入口，保留冻结协议／模型／地址门槛；默认是在线评测，会调用真实模型。显式加 `--check-only` 仅检查冻结输入，加 `--replay=<历史JSON或JSONL>` 仅重统计保存的判定，两者均在读取模型设置／余额预检／创建模型驱动器前返回，真实模型调用为 0；记录与分母见[可靠性报告](reviews/2026-10-02-source-audit-reliability.md)。
- 密钥只通过请求头发给配置的模型服务。公开设置仅含 URL、模型名、是否配置以及配置来源；错误消息只含变量名和规则。来源调查日志使用固定提示；评测异常保留分类和 HTTP 状态，不保留上游原始文本／请求头。
- 本机 API 仍只监听 `127.0.0.1`。环境兼容只解决配置输入方式，不证明公网部署、访问权限、费用隔离或赛事最终验收。
