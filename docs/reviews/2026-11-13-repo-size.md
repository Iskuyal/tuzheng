## 为什么 clone 不会因此变小

`git rm --cached` 只把路径从索引里去掉，提交历史里的 blob 一个都不会消失；上面的旧版 `silent.mp4` 就是现成的例子。clone 要下载的是对象库，不是当前工作树，所以：

- 移出索引 + 提交，只影响之后 checkout 出来的文件，`.git` 与已有 clone 都不变；
- 要让新 clone 真正变小，必须重写历史（`git filter-repo --invert-paths`），那会改写提交 SHA，并让材料里登记的文件哈希全部失效（[材料清单](../submission/materials.json) 的 `formalVideo.sha256`、证据 JSON 里的 `bytes`/`sha256`），还需要 force push。**这一步涉及不可逆的材料变更，本轮不做，需负责人确认。**

## 可执行方案

| 路径 | 做法 | 影响 | 状态 |
| --- | --- | --- | --- |
| A 评审侧即时缓解 | GitHub `Code` → `Download ZIP`，或 `git clone --depth 1` | 只取当前快照，不下载历史；零风险、可立即用 | **已落到 README** |
| B 移出大文件索引 | `node scripts/prune-large-files.mjs --apply` 后由负责人提交 | 保留本地文件，可逆；减当前树与后续 checkout 体积，**不减 `.git`/clone** | 只提供脚本，本轮**未执行** |
| C 重写历史 | `git filter-repo` 剔除视频路径后 force push | 真正减小 clone；改写 SHA、材料哈希失效、破坏已有 clone | 需负责人确认，本轮**不做** |

选 B 时还有两件人工决定的事：

1. 被移出的文件会变成未跟踪状态，需要补 `.gitignore` 或 `.git/info/exclude`，否则 `git status` 一直脏。脚本不写忽略规则。
2. [材料清单](../submission/materials.json) 登记了 `tuzheng-competition-demo-2026-10-28.mp4` 与 `tuzheng-competition-demo-2026-10-18-silent.mp4` 两个交付物。移出索引后，新 clone 里没有这两个文件，`npm run verify:materials` 会报「交付材料不存在」。清单是否调整、视频改由何处托管，需要负责人决定；本轮未改 `materials.json`。

## 评审获取指引

[仓库根 README](../../README.md) 的「快速开始」下方新增了「评审获取方式」，写明两种不取历史的获取方式（Download ZIP、`git clone --depth 1`），并说明完整历史仍在仓库中。README 不承诺体积数字，只说明取舍。

## 工具

[scripts/prune-large-files.mjs](../../scripts/prune-large-files.mjs)：Node ESM，无第三方依赖，默认 dry-run。

| 用法 | 行为 |
| --- | --- |
| `node scripts/prune-large-files.mjs` | 只读：列出候选文件表格、累计体积、预计剩余体积；不改索引、不改磁盘 |
| `--min-size=<MiB>` | 改阈值（默认 5） |
| `--all-large` | 不限扩展名，只看体积 |
| `--apply` | 对每个候选执行 `git rm --cached <path>`，保留本地文件，并打印后续提示 |
| `--help` | 用法与风险摘要 |

退出码：0 正常；1 有文件移除失败；2 参数或 git 调用错误。脚本头部注释写明了「历史仍含 blob、clone 不会变小、真正变小需 filter-repo 且会改 SHA 与材料哈希、需负责人确认」。

## 边界

本轮**未**重写历史、**未**删除任何视频或大文件（`docs/submission` 下 `*.mp4`、`*.webm` 全部保留）、**未**改动任何受控内容（`.mp4`/`.webm`/`materials.json` 字节未变，工作区未产生暂存删除）、**未**执行脚本的 `--apply`（即未跑 `git rm --cached`）、**未**提交、**未** force push。改动只有三处：新增 `scripts/prune-large-files.mjs`、新增本报告、README 增一节。

## 复现命令

```bash
git ls-tree -r -l HEAD | sort -k4 -nr | head -12          # 最大受控文件
git ls-tree -r -l HEAD | awk '{s+=$4} END {print s}'      # 受控体积合计（字节）
git count-objects -vH                                     # size-pack
git verify-pack -v .git/objects/pack/pack-*.idx | sort -k3 -nr | head
git log --all --find-object=<blob>                        # 追某个 blob 的来历
node scripts/prune-large-files.mjs                        # 瘦身预演
```
