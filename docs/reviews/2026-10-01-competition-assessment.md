## 实现与规范评估

### 已具备的完整路径

1. 单图：上传 / 样例 → 模型观察 → 用户确认更正 → 程序增长率 → 证据卡；缺失、单位、时间、零基数有确认边界。
2. 跨图与纵轴：口径元素先核对；确认值进入比较；不一致先于缺失；重置与迟到请求隔离；原轴与零起点对照不等于判假。
3. 来源：图文主张 → 模型选择检索 / 比较 / 追问 → 适用性与引用校验 → 分主张结果、未展开内容与工具轨迹。
4. 补证：同调查 ID 与模型对话恢复，输入指纹绑定、并发恢复拒绝、调用与工具轮预算继承，用户回答不冒充官方材料。
5. 建议：逐处原句、处理方式、理由与引用；数值 / 方向校验、拒绝原因和程序兜底；显式采用后旧结果转历史。
6. 修订：依据官方声明明确的替代关系，更新有效值、结论、建议与引用角色；没有声明的分歧不进入能力声明。

设置支持双协议、HTTPS 与真实回环校验、损坏格式重建、连接分类错误；前后端与共享层职责清楚。历史审查确认的引用贯通、方向改写、补证隔离等缺陷已有本地回归，不能将过去缺陷继续写成未修，但也不能由本地回归推断线上稳定性重新通过。

## 建议收口顺序与成功标准

1. **当前版本在线复验**：先对五道冻结演示题与修订引用 / 方向 / 补证隔离的必要回归小范围复验，记录 SHA 与完整配置。成功标准是每题实际记录、失败也入档，不用历史通过覆盖当前失败。
2. **密钥要求处理**：在不泄露 / 回传密钥的前提下，决定环境变量兼容方案，或取得组委会对本机方式的明确认可。成功标准是运行证据或明确答复；仅解释安全理由不足以标记符合。
3. **完成评审可访问材料**：处理仓库权限，录制 5-8 分钟 1080p MP4，补团队报名信息、视频链接与另一台环境人工验证。成功标准是实际访问和成品可打开，不能把脚本当成视频。
4. **冻结正式提交版本**：处理 PR #31 的归属，选择提交 SHA，对该版本完成离线检查与 PDF 重建。成功标准是仓库、视频、PDF 与说明引用同一最终基线。
5. **可选加分**：优先独立预留截图与少量真实用户任务、首屏性能 / 键盘读屏检查，再决定是否做受保护公网演示。没有实测前不加入交付声明。
