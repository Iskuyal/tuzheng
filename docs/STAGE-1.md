# 阶段一：单图图内审计闭环

**阶段状态：待开始。** 本阶段的交付不是一套静态页面，而是一条能在 Windows 本地运行、能调用云端视觉模型、允许用户纠正识别、再由程序计算并解释结果的完整路径。

## 用户故事

作为只拿到截图的读者，我想上传图片或选一个样例，看见图表标题与标注数字是否自洽；当模型读错数字时，我能先纠正，再看到可靠的图内计算结果；当证据不够时，系统告诉我还不能判断什么。

## 交付范围

1. Vue 3＋Vite＋TypeScript 前端，以及 Node.js＋Express＋TypeScript 接口；单个根目录开发脚本同时启动两者。API 密钥只在服务端环境变量中，仓库提供 `.env.example`。
2. 首页有图片上传和三个自制样例入口：**矛盾**（80、100，标题 40%）、**一致**（80、100，标题 25%）、**无法读清**（一处关键标签模糊）。样例内容和期望结果分开保存。
3. 服务端把图片交给可配置的云端视觉模型，要求其返回结构化观察值：标题原文、所读到的年份／类别、数值、单位和无法辨认项。严格校验模型输出；不从柱子高度臆造无标签的精确数值。
4. 前端先展示模型观察值，让用户确认或更正。未确认时不输出确定的数值结论。用户更正后可重新审计。
5. 确定性检查器只支持一个明确规则：两个已确认数值的增长率 `(新值－旧值) ÷ 旧值`。旧值为 0、单位不一致、时间顺序不清或数字缺失时，返回「需要确认／无法判断」。
6. 结果卡展示图内结论、标题原文、输入数字、公式和计算值。结论状态至少有「图内一致」「图内矛盾」「需要确认」；页面明确说明**这不是对真实原始数据的核实**。
7. 提供加载、超时、模型输出异常、格式不支持和密钥未配置等状态。缺少 API 密钥时，内置样例可用标明「预置示例」的观察值走检查流程，但不能伪装成实时模型结果。

图片来源定位在本阶段以用户裁剪、提取原文与原图并排显示实现；不把自动像素级框选设为通过条件。

## 建议的最小结构

- 前端负责上传、图片预览、观察值确认与结果卡。
- 服务端负责图片大小／类型检查、模型适配与结构化校验。
- 共享领域类型区分**模型观察值、用户确认值、检查结果**，避免把三者混作一个 `data` 对象。
- 增长率检查器是纯 TypeScript 函数，可以独立测试；未来其他检查规则接入同一结果语义。

实现可以调整目录和库选型，但仍须保持一个根目录 `npm install`、`npm run dev` 的 Windows 使用方式。首版数据保存在本地文件或内存中，不引入数据库服务、Docker、WSL 或本地推理环境。

## 验收清单

- [ ] 在干净工作树中安装依赖并运行前后端；浏览器可打开首页并使用三个样例。
- [ ] 「80 → 100、标题 40%」在用户确认数值后显示 **25%**、公式及「图内矛盾」。
- [ ] 「80 → 100、标题 25%」显示「图内一致」。
- [ ] 模糊数字样例不会生成一个自信的百分比；手动更正后可重算。
- [ ] 上传一张新的清晰图片可走真实模型路径；若没有配置密钥，只能记录该项未验证，不能标为通过。
- [ ] 错误状态对用户可理解，服务端日志与前端资源中均不泄露 API 密钥。
- [ ] 对增长率边界和三类结果有自动化行为测试；前端关键路径至少人工验证一次。
- [ ] README 说明安装、配置、运行、当前能力边界与尚未交付的后续阶段；记录实际测试结果。
