# 图证

图证帮助只有图表截图的读者检查标题与图中标注是否自洽。阶段一的单主张审计路径仍可选择原有样例或上传图片，确认/更正观察值后由程序计算增长率；阶段二任务 01—07 已本地验收，三主张预置示例支持逐条查看、修改、确认、重算，可查看本次会话的审计记录、一键重置。阶段三支持最多两张图的口径核对和柱状图纵轴风险提示，核心路径从 320px 起有自动化浏览器测试。阶段四的来源核验把图文主张对照固定国家统计局资料库，其中任务 03 能把一段短配文拆成直接陈述、可检查推断与观点，并指出推断缺哪一项依据；任务 04 能就一条具体主张提出一个会改变结论的问题，用户补充标为「用户提供」后沿同一条调查记录恢复调查，改动图片或配文则旧结论立即失效、历史结论只作历史展示。模型设置支持 OpenAI Responses 兼容与 Anthropic Messages 两种协议，可按协议分别保存地址、模型与密钥并切换。

**阶段一状态：本地可验证功能验收已通过；真实云端视觉读取已于 2026-09-26 用三个团队自制样例通过（单次 3.2—4.4 秒）；独立 UI 评审同日三轮复审达到 9/10 门槛且无必须修项。** 样例使用明确标为“预置示例”的观察值；只有上传图片并点击读取才会请求你配置的模型服务，系统不会把预置结果说成实时 AI 输出。

独立 UI 评审：第 33 轮 8.4/10，其建议已落地；2026-09-26 用同一提示与截图口径连做三轮委派复审，35 轮 7.5 → 36 轮 8.4 → **37 轮 9.0 且无必须修项**，9/10 门槛达成。评审截图可用 `node e2e/review-screenshots.mjs <输出目录>` 复现。

## Windows 快速开始

需要 Node.js 22.12 或更高的 22.x，或 Node.js 24.x；阶段验收使用 Node 24.16、npm 11.17。

```powershell
npm install
npm run dev
```

打开 <http://127.0.0.1:5173>。根目录脚本会同时启动 Vue/Vite 页面和 Express API；API 默认使用 `127.0.0.1:3001`。

要启用新图片的视觉读取，打开页面右上角的「模型设置」，先选择「接口协议」：**OpenAI Responses 兼容**（默认）或 **Anthropic Messages 兼容**。两种协议各自保存地址、模型与密钥，切换协议会带出该协议已存配置；旧版本保存的单份设置会在读取时自动迁移为 Responses 配置。「常用模型预设」按协议列出常用多模态型号，两种协议都覆盖厂商官方与中转站：Anthropic 侧有 DeepSeek 官方 `deepseek-flash`（已实测）、阿里云百炼 `qwen3.8-flash`、智谱 `glm-5.3-flash`、OpenCode Zen、OpenRouter 与 Anthropic 官方；Responses 侧有 DeepSeek 官方、commandcode 网关、OpenCode Zen、OpenRouter 与 OpenAI 官方。选取即填入地址与型号并显示出处与验证状态；预设只收录支持图片输入的型号，避免接入纯文本模型后读图不可用。「Anthropic Messages」卡片不绑定 Claude 模型：任何实现 Messages 协议的端点都可以填（官方 Anthropic、提供 Anthropic 兼容面的第三方服务，或自建 LiteLLM 之类的代理），模型名按该端点支持的填写。Base URL 都只填接口根路径（例如以 `/v1` 结尾），应用会按协议自行调用 `/responses` 或 `/messages`；不要填入 `/chat/completions`、`/responses` 或 `/messages` 的完整接口地址，服务端会在保存时拒绝这类误填并保留原设置。可先点「测试连接」检查当前表单参数：Responses 发送一条 JSON Schema 短请求，Anthropic 发送一条强制工具调用短请求；测试不会保存设置或发送图片，图片识别仍需上传样例验证。默认填入的 `https://api.openai.com/v1` / `gpt-4.1-mini` 与 `https://api.anthropic.com/v1` / `claude-sonnet-4-6` 是示例值，可替换；团队已用第三方 Responses 兼容端点完成真实读取验收（见 [阶段一验收记录](docs/STAGE-1.md)和[阶段三复验记录](docs/evidence/stage-3-live-vision-2026-09-27.md)），该默认端点本身未做过调用。远程服务地址必须使用 HTTPS；本机回环服务可用 HTTP。设置只经本机 Node 服务端保存到 `%LOCALAPPDATA%\TuZheng\settings.json`；读取接口只返回 URL、模型名和密钥是否已配置，不回传密钥。`.env.example` 仅保留可选 API 端口。设置文件使用当前 Windows 账户的本机文件权限；同一账户下运行的其他程序也有权读取。上传的新图会发送到设置页中指定的服务；预置示例不调用云端模型。

### 在 WebStorm 里构建与运行

可以不碰终端，直接在 IDE 里完成：打开根目录 `package.json`，点 `dependencies` 上方的“Run 'npm install'”提示装依赖，再点 `scripts` 里各条命令左侧的 ▶ 运行。`dev` 会同时起前后端，`build` 做类型检查加打包，`test` 跑行为测试。全部脚本也能在 View → Tool Windows → npm 里看到。

`tsconfig.json` 是一份“解决方案”配置：它自己不检查任何文件，只指向 `tsconfig.web.json`（`web/` 与 `shared/`，带 DOM 与 vite/client 类型）和 `tsconfig.server.json`（`server/`、`shared/`、`tests/`，带 Node 类型）。这是刻意的——一旦让它认领源文件，IDE 就会用缺少这些类型的设置去检查代码，报出并不存在的错误。命令行与 IDE 的检查入口都保持为 `npm run typecheck` 与 `npm run build`。

计算使用 `(较新值 - 较早值) / 较早值 × 100`。计算值四舍五入到两位小数后，与标题中的百分比精确相等才判为“图内一致”；数值、单位、时间顺序、图中文字依据或标题主张不完整时降级为“需要确认”。

上传文件只在请求期间保存在服务端内存，不写入项目目录。模型读取失败、超时、图片格式不支持或密钥未配置时，页面显示对应说明。模型设置文件位于当前 Windows 用户的 LocalAppData；同一 Windows 账户下的进程也可读取该文件。

## 本地验证

```powershell
npm test          # 共享规则、API 与样例的行为测试
npm run eval:samples  # 18 张预置自制图与 5 组跨图配对的固定评测，不请求真实模型
npm run verify:sample-renders  # 用 Edge 重新渲染 SVG，逐张核对同名 PNG
npm run eval:source-audit  # 19 题固定题集的有检索/无检索配对评测（含补证两阶段），会调用真实模型；见下方说明
npm run test:e2e  # 浏览器端到端验收（需要时自动启动前后端，使用系统自带 Edge）
npm run build
npx tsc -b tsconfig.json
```

`npm run eval:source-audit` 会请求真实模型，所以与 `npm test` 分开：它按 `samples/source-audit-questions.json` 与 `samples/source-audit-expectations.json` 逐题跑有检索和无检索两臂；带补证阶段的题（题面写了人写定的 clarifyAnswer）在初查提出追问后沿同一段对话恢复、补证前后分别判定，未追问时不编造恢复记录。运行前先核对图片指纹、资料库指纹、预算常量、题集覆盖与补证配置成对冻结，任一项不符即停止；默认每臂每题 3 次，支持 `--runs`／`--arms`／`--ids`／`--record`／`--strict`，开跑前打印计划请求数与账户余额。当前模型配置与冻结配置不一致时它会拒绝运行，不会拿别的模型的结果冒充。

`npm run test:e2e` 只走预置示例与替身响应，不需要 API Key；来源核验用例用替身覆盖页面路径，真实模型的在线结果单列在[验收记录](docs/evidence/stage-4-source-audit-2026-09-29.md)里，两者分开计数；默认在 320×640、390×844 和 1280×900 三个视口各跑一遍。已在本机运行的 `npm run dev` 会被复用，没有则自动启动并在结束后关闭。浏览器是系统自带 Edge（`channel: "msedge"`）；机器上没有 Edge 时，可执行 `npx playwright install chromium` 并去掉 `playwright.config.ts` 里的 `channel` 一行。

阶段验收细节与未验证项见 [分阶段路线图](docs/PHASES.md) 和 [阶段一验收记录](docs/STAGE-1.md)。样例图片、预置观察值与预期结果分开保存：图片在 `web/public/samples/`，观察值在 `shared/samples.ts`，原有预期在 `samples/expectations.json`，18 张图的独立评测预期与使用许可在 [fixed-evaluation.json](samples/fixed-evaluation.json)，固定 SVG／PNG 指纹在 [image-checksums.json](samples/image-checksums.json)。样例以 SVG 保存供页面展示；上传与视觉读取只接受 PNG、JPG、WebP，因此同内容另存了同名的 PNG 栅格渲染。预置评测不会发送图片给模型；需要验证真实视觉读取时可上传对应 PNG 并点击读取。

## 产品边界

当前可检查一张或两张截图中明确可见的主张、数字和口径，提示柱状图纵轴的呈现风险，并在 CPI 这一个专题上把图文主张对照固定国家统计局资料库做来源核验。图内或跨图一致性都不代表原始数据真实或虚假；来源结论只说明「与所引发布是否一致」，不判断造假或作者动机，也不证明现实数据。来源核验只覆盖固定资料库内的 CPI 材料，运行时不抓取开放网络；任意网页检索、RAG、CSV／手填来源、MCP、登录协作和公网部署留待后续阶段。阶段四任务 01、02、03、04 已实现在线验收：02 的 12 题配对评测（×2 臂 ×3 次，三轮）显示有检索臂主张状态正确率 91.3%、无检索臂 39.6%；03 把题集扩到 17 题并整组复跑五轮（每轮 17 题 ×2 臂 ×3 次），有检索臂 97.2%／90.3%／100.0%／96.8%／92.6%，无检索臂 29.7%／32.5%／43.5%／36.6%／20.8%；04 把题集扩到 19 题并整组复跑一轮（19 题 ×2 臂 ×3 次＋补证恢复段），有检索臂 90.0%（54/60）、无检索臂 30.5%，恢复段 3/3 通过且补充套用 3/3，q19 资料已覆盖 0 次追问；虚构引用与无适用来源越界在三批评测中均为 0，推断缺口、观点不做真假判定、「超过三条不静默丢弃」、先检索后追问与改动即失效都有真实运行或浏览器证据。题型全部是开发题、没有预留题，不外推准确率；03 五轮上游失败 25%—50%（末尾确认是提供方余额耗尽），04 最终轮上游失败 0、但中途三轮因程序缺陷或审查修复（空 content 消息、`omittedClaims` 超限被整份拒绝、结论对照补漏配对主张）废弃重跑；主张分类准确率未单独统计，q11 出现过模型给配文主张补图上的比较方式，q18 追问率无检索臂 2/3 存在漂移，这些都是仍然成立的局限。任务 05—06（有依据的修改建议、反证复查）尚未实现。
