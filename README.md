# 图证

图证帮助只有图表截图的读者检查标题与图中标注是否自洽。阶段一的单主张审计路径仍可选择原有样例或上传图片，确认/更正观察值后由程序计算增长率；阶段二任务 01—07 已本地验收，三主张预置示例支持逐条查看、修改、确认、重算，可查看本次会话的审计记录、一键重置。阶段三支持最多两张图的口径核对和柱状图纵轴风险提示，核心路径从 320px 起有自动化浏览器测试。模型设置支持 OpenAI Responses 兼容与 Anthropic Messages 两种协议，可按协议分别保存地址、模型与密钥并切换。

**阶段一状态：本地可验证功能验收已通过；真实云端视觉读取已于 2026-09-26 用三个团队自制样例通过（单次 3.2—4.4 秒）；独立 UI 评审同日三轮复审达到 9/10 门槛且无必须修项。** 样例使用明确标为“预置示例”的观察值；只有上传图片并点击读取才会请求你配置的模型服务，系统不会把预置结果说成实时 AI 输出。

独立 UI 评审：第 33 轮 8.4/10，其建议已落地；2026-09-26 用同一提示与截图口径连做三轮委派复审，35 轮 7.5 → 36 轮 8.4 → **37 轮 9.0 且无必须修项**，9/10 门槛达成。评审截图可用 `node e2e/review-screenshots.mjs <输出目录>` 复现。

## Windows 快速开始

需要 Node.js 22.12 或更高的 22.x，或 Node.js 24.x；阶段验收使用 Node 24.16、npm 11.17。

```powershell
npm install
npm run dev
```

打开 <http://127.0.0.1:5173>。根目录脚本会同时启动 Vue/Vite 页面和 Express API；API 默认使用 `127.0.0.1:3001`。

要启用新图片的视觉读取，打开页面右上角的「模型设置」，先选择「接口协议」：**OpenAI Responses 兼容**（默认）或 **Anthropic Messages**。两种协议各自保存地址、模型与密钥，切换协议会带出该协议已存配置；旧版本保存的单份设置会在读取时自动迁移为 Responses 配置。「Anthropic Messages」卡片不绑定 Claude 模型：任何实现 Messages 协议的端点都可以填（官方 Anthropic、提供 Anthropic 兼容面的第三方服务，或自建 LiteLLM 之类的代理），模型名按该端点支持的填写——但对方是否支持图片块与强制工具调用需要在页面上实测。Base URL 都只填接口根路径（例如以 `/v1` 结尾），应用会按协议自行调用 `/responses` 或 `/messages`；不要填入 `/chat/completions`、`/responses` 或 `/messages` 的完整接口地址，服务端会在保存时拒绝这类误填并保留原设置。可先点「测试连接」检查当前表单参数：Responses 发送一条 JSON Schema 短请求，Anthropic 发送一条强制工具调用短请求；测试不会保存设置或发送图片，图片识别仍需上传样例验证。默认填入的 `https://api.openai.com/v1` / `gpt-4.1-mini` 与 `https://api.anthropic.com/v1` / `claude-sonnet-4-6` 是示例值，可替换；团队已用第三方 Responses 兼容端点完成真实读取验收（见 [阶段一验收记录](docs/STAGE-1.md)和[阶段三复验记录](docs/evidence/stage-3-live-vision-2026-09-27.md)），该默认端点本身未做过调用。远程服务地址必须使用 HTTPS；本机回环服务可用 HTTP。设置只经本机 Node 服务端保存到 `%LOCALAPPDATA%\TuZheng\settings.json`；读取接口只返回 URL、模型名和密钥是否已配置，不回传密钥。`.env.example` 仅保留可选 API 端口。设置文件使用当前 Windows 账户的本机文件权限；同一账户下运行的其他程序也有权读取。上传的新图会发送到设置页中指定的服务；预置示例不调用云端模型。

### 在 WebStorm 里构建与运行

可以不碰终端，直接在 IDE 里完成：打开根目录 `package.json`，点 `dependencies` 上方的“Run 'npm install'”提示装依赖，再点 `scripts` 里各条命令左侧的 ▶ 运行。`dev` 会同时起前后端，`build` 做类型检查加打包，`test` 跑行为测试。全部脚本也能在 View → Tool Windows → npm 里看到。

`tsconfig.json` 是一份“解决方案”配置：它自己不检查任何文件，只指向 `tsconfig.web.json`（`web/` 与 `shared/`，带 DOM 与 vite/client 类型）和 `tsconfig.server.json`（`server/`、`shared/`、`tests/`，带 Node 类型）。这是刻意的——一旦让它认领源文件，IDE 就会用缺少这些类型的设置去检查代码，报出并不存在的错误。命令行与 IDE 的检查入口都保持为 `npm run typecheck` 与 `npm run build`。

## 本地验证

```powershell
npm test          # 共享规则、API 与样例的行为测试
npm run eval:samples  # 18 张预置自制图与 5 组跨图配对的固定评测，不请求真实模型
npm run verify:sample-renders  # 用 Edge 重新渲染 SVG，逐张核对同名 PNG
npm run test:e2e  # 浏览器端到端验收（需要时自动启动前后端，使用系统自带 Edge）
npm run build
npx tsc -b tsconfig.json
```

`npm run test:e2e` 只走预置示例，不需要 API Key；默认在 320×640、390×844 和 1280×900 三个视口各跑一遍。已在本机运行的 `npm run dev` 会被复用，没有则自动启动并在结束后关闭。浏览器是系统自带 Edge（`channel: "msedge"`）；机器上没有 Edge 时，可执行 `npx playwright install chromium` 并去掉 `playwright.config.ts` 里的 `channel` 一行。

阶段验收细节与未验证项见 [分阶段路线图](docs/PHASES.md) 和 [阶段一验收记录](docs/STAGE-1.md)。样例图片、预置观察值与预期结果分开保存：图片在 `web/public/samples/`，观察值在 `shared/samples.ts`，原有预期在 `samples/expectations.json`，18 张图的独立评测预期与使用许可在 [fixed-evaluation.json](samples/fixed-evaluation.json)，固定 SVG／PNG 指纹在 [image-checksums.json](samples/image-checksums.json)。样例以 SVG 保存供页面展示；上传与视觉读取只接受 PNG、JPG、WebP，因此同内容另存了同名的 PNG 栅格渲染。预置评测不会发送图片给模型；需要验证真实视觉读取时可上传对应 PNG 并点击读取。

## 产品边界

当前可检查一张或两张截图中明确可见的主张、数字和口径，并提示柱状图纵轴的呈现风险。图内或跨图一致性都不代表原始数据真实或虚假；来源核验、RAG、MCP、登录协作和公网部署留待后续阶段。
