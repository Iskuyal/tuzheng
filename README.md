# 图证

图证帮助只有图表截图的读者检查标题与图中标注是否自洽。阶段一的单主张审计路径仍可选择原有样例或上传图片，确认/更正观察值后由程序计算增长率；阶段二任务 01—07 已本地验收，三主张预置示例支持逐条查看、修改、确认、重算，可查看本次会话的审计记录、一键重置。阶段三支持最多两张图的口径核对和柱状图纵轴风险提示，核心路径从 320px 起有自动化浏览器测试。阶段四的来源核验把图文主张对照固定国家统计局资料库，其中任务 03 能把一段短配文拆成直接陈述、可检查推断与观点，并指出推断缺哪一项依据；任务 04 能就一条具体主张提出一个会改变结论的问题，用户补充标为「用户提供」后沿同一条调查记录恢复调查，改动图片或配文则旧结论立即失效、历史结论只作历史展示；任务 05 在核验结束后给出逐处有据的修改建议——每处改动关联原句、理由与当前有效引用，错误数值只能用所引来源的正确值替换，未解决的部分保留限定或建议删除，建议由用户显式采用才写入配文，输入或引用一变旧建议立即撤回并只作历史展示。模型设置支持 OpenAI Responses 兼容与 Anthropic Messages 两种协议，可按协议分别保存地址、模型与密钥并切换。

**阶段一状态：本地可验证功能验收已通过；真实云端视觉读取已于 2026-09-26 用三个团队自制样例通过（单次 3.2—4.4 秒）；独立 UI 评审同日三轮复审达到 9/10 门槛且无必须修项。** 样例使用明确标为“预置示例”的观察值；只有上传图片并点击读取才会请求你配置的模型服务，系统不会把预置结果说成实时 AI 输出。

## Windows 快速开始

需要 Node.js 22.12 或更高的 22.x，或 Node.js 24.x；阶段验收使用 Node 24.16、npm 11.17。

```powershell
npm install
npm run dev
```

打开 <http://127.0.0.1:5173>。根目录脚本会同时启动 Vue/Vite 页面和 Express API；API 默认使用 `127.0.0.1:3001`，网页默认 `127.0.0.1:5173`。两个端口都可以在根目录 `.env` 里改（`PORT`、`WEB_PORT`），或在启动前设置同名进程变量，前端代理使用同一个 `PORT`。**端口固定、不会自动换**：`npm run dev` 先跑 `npm run dev:ports` 预检，哪一端被占用就直接退出并给出清理命令（`netstat -ano | findstr :3001` → `taskkill /F /PID <PID>`），vite 侧另开了 `strictPort` 兜底——这样 README、演示脚本与编辑器里配置的地址不会悄悄变成 5174。

### 在 WebStorm 里构建与运行

可以不碰终端，直接在 IDE 里完成：打开根目录 `package.json`，点 `dependencies` 上方的“Run 'npm install'”提示装依赖，再点 `scripts` 里各条命令左侧的 ▶ 运行。`dev` 会同时起前后端，`build` 做类型检查加打包，`test` 跑行为测试。全部脚本也能在 View → Tool Windows → npm 里看到。

`tsconfig.json` 是一份“解决方案”配置：它自己不检查任何文件，只指向 `config/tsconfig.web.json`（`web/` 与 `shared/`，带 DOM 与 vite/client 类型）、`config/tsconfig.server.json`（`server/`、`shared/`、`scripts/`、`tests/`，带 Node 类型）与 `config/tsconfig.e2e.json`（浏览器测试，带 Node 与 DOM 类型）。这是刻意的——一旦让它认领源文件，IDE 就会用缺少这些类型的设置去检查代码，报出并不存在的错误。命令行与 IDE 的检查入口都保持为 `npm run typecheck` 与 `npm run build`。

## 技术架构

```mermaid
flowchart LR
    A[Vue 3 页面] --> B[Express API<br/>仅监听 127.0.0.1]
    B --> C[视觉适配器<br/>Responses / Messages]
    B --> D[来源调查编排器<br/>受限工具循环]
    D --> E[固定资料库<br/>构建期写死]
    B --> F[确定性计算与判定]
    F --> A
```

三层结构，没有数据库、Docker 或前端状态管理库；配置与目录职责见[项目结构](docs/STRUCTURE.md)。

- **`web/`** — Vue 3 + Vue Router + Vite。四个页面：着陆页、审计工作台、来源核验、模型设置。前端无持久化，审计状态只存在于当前会话内存，刷新即清空；审计记录与重置都在这一层完成。
- **`server/`** — Node + Express 5，只监听 `127.0.0.1`。负责模型调用、结构校验、工具循环编排与设置文件读写。上传图片只在请求期间驻留内存，不写入项目目录。
- **`shared/`** — 协议无关的纯 TypeScript 领域层：增长率计算、结果分级、跨图口径比对、纵轴风险、引用校验与结论组合。这一层看不到任何模型协议。

**模型只读不算。** 模型负责读图、提取原文与数值、做语义匹配；所有百分比、差值、单位换算和结论判定都由 `shared/` 里的确定性代码完成。模型输出先经 Zod 结构校验、再由用户确认，才参与判定；读图提示词明确禁止模型给出确认值、增长率或结果状态。模型对主张的分类判断（直接陈述／可检查推断／观点）也要经过文字依据校验才能参与判定。

**两种协议一个接口。** `server/app.ts` 定义 `VisionAdapter` 与 `SourceInvestigationDriver` 两个窄接口，OpenAI Responses 与 Anthropic Messages 各一个实现，领域层与页面完全看不到协议差异。两个适配器都强制结构化输出（Responses 用严格 JSON Schema，Messages 用强制工具调用），并各自处理提供方的兼容差异。

**有界 Agent 循环。** 来源核验的编排器只给模型四个受限工具——检索资料库、比较数值、请求确认、汇报结论；服务端逐个校验工具名与参数，按轮次与总量计预算，被拒绝的调用连原因一起留在轨迹里。检索只在进程内的固定资料库里打分排序，运行时不访问开放网络，也不执行模型生成的任何代码。

```powershell
npm run eval:samples  # 18 张预置自制图与 5 组跨图配对的固定评测，不请求真实模型
npm run verify:sample-renders  # 用 Edge 重新渲染 SVG，逐张核对同名 PNG
npm run eval:source-audit  # 22 题固定题集的有检索/无检索配对评测（含补证与修改建议），会调用真实模型；见下方说明
npm run test:e2e  # 浏览器端到端验收（需要时自动启动前后端，使用系统自带 Edge）
npm run build
npx tsc -b tsconfig.json
node docs/submission/build-report.mjs         # 从 HTML 源重建技术 PDF 并校验页数不超过 30 页
node e2e/submission-screenshots.mjs           # 生成提交材料用的界面截图（替身响应；需先 npm run dev）
```

`node docs/submission/build-report.mjs` 用系统 Edge 把 [technical-report.html](docs/submission/technical-report.html) 打印成 A4 PDF 并自动回填目录页码，页数超过赛事要求的 30 页会以退出码 1 结束（加 `--check` 只校验页数）。`node e2e/submission-screenshots.mjs` 用替身响应重放界面并把截图写入 `docs/submission/assets/`，不调用真实模型、不需要密钥。

`npm run eval:source-audit` 会请求真实模型，所以与 `npm test` 分开：它按 `samples/source-audit-questions.json` 与 `samples/source-audit-expectations.json` 逐题跑有检索和无检索两臂；带补证阶段的题（题面写了人写定的 clarifyAnswer）在初查提出追问后沿同一段对话恢复、补证前后分别判定，未追问时不编造恢复记录。判定除了主张状态与引用，还独立复算修改建议的全量不变量（不得引入原配文、本次主张与所引来源之外的数值／月份／范围／因果加强表述；未解决主张必须保留限定或建议删除），不依赖服务端的校验实现。运行前先核对图片指纹、资料库指纹、预算常量、题集覆盖与补证配置成对冻结，任一项不符即停止；默认每臂每题 3 次，支持 `--runs`／`--arms`／`--ids`／`--record`／`--strict`，开跑前打印计划请求数与账户余额。当前模型配置与冻结配置不一致时它会拒绝运行，不会拿别的模型的结果冒充。

`npm run test:e2e` 只走预置示例与替身响应，不需要 API Key；来源核验用例用替身覆盖页面路径，真实模型的在线结果单列在[验收记录](docs/evidence/stage-4-source-audit-2026-09-29.md)里，两者分开计数；默认在 320×640、390×844 和 1280×900 三个视口各跑一遍。已在本机运行的 `npm run dev` 会被复用，没有则自动启动并在结束后关闭。浏览器是系统自带 Edge（`channel: "msedge"`）；机器上没有 Edge 时，可执行 `npx playwright install chromium` 并去掉 `config/playwright.config.ts` 里的 `channel` 一行。

阶段验收细节与未验证项见 [分阶段路线图](docs/PHASES.md) 和 [阶段一验收记录](docs/STAGE-1.md)。样例图片、预置观察值与预期结果分开保存：图片在 `web/public/samples/`，观察值在 `shared/samples.ts`，原有预期在 `samples/expectations.json`，18 张图的独立评测预期与使用许可在 [fixed-evaluation.json](samples/fixed-evaluation.json)，固定 SVG／PNG 指纹在 [image-checksums.json](samples/image-checksums.json)。样例以 SVG 保存供页面展示；上传与视觉读取只接受 PNG、JPG、WebP，因此同内容另存了同名的 PNG 栅格渲染。预置评测不会发送图片给模型；需要验证真实视觉读取时可上传对应 PNG 并点击读取。

### 持续集成

推送与合并请求会由 [CI](.github/workflows/ci.yml) 自动执行文档本地链接检查、类型检查、构建、`npm test`、`npm run eval:samples` 与三视口 `npm run test:e2e`。CI **只跑离线路径**：不配置任何模型密钥，也不执行 `npm run eval:source-audit`，因此不会产生模型费用，评测结果也不会写回仓库。

CI 的拦截点本身做过人为变红验证（阶段五 07）：注入一处类型错误后 [run 36723291466](https://github.com/Iskuyal/web-match/actions/runs/36723291466) 41 秒红在类型检查步骤（同一注入在本机 `npm test` 仍全绿——2026-09-30 实测，当时 332 条；vitest 走 esbuild 只剥离类型不做检查，只有 `npm run typecheck` 能拦）；注入一处断言失败后 [run 36723673814](https://github.com/Iskuyal/web-match/actions/runs/36723673814) 红在 `npm test` 步骤；两处注入都未合并，回退后 main [run 36724007809](https://github.com/Iskuyal/web-match/actions/runs/36724007809) 恢复绿色。逐次记录见 [路线图阶段五 07 一节](docs/PHASES.md)。

两处仍需在本机手动执行，不进入 CI：`npm run eval:source-audit` 会调用真实模型并产生费用，需要本机已保存的模型配置；`npm run verify:sample-renders` 逐字节比对 PNG 的 SHA-256，结果依赖本机 Edge 版本的字体栅格化。2026-09-30 实测：当前 `windows-latest` 镜像（`windows-2025-vs2026`）的 Edge 与开发机栅格化结果不同，该信号在 CI 上为 **0/18** 失败；因此它在工作流里是 `continue-on-error: true` 的不阻塞信号，失败不拦截合并，逐字节同源核对只在开发机（18/18）作为证据。

## 产品边界

当前可检查一张或两张截图中明确可见的主张、数字和口径，提示柱状图纵轴的呈现风险，并把 CPI 与社会消费品零售总额环比主张对照固定国家统计局资料库做来源核验。图内或跨图一致性都不代表原始数据真实或虚假；来源结论只说明「与所引发布是否一致」，不判断造假或作者动机，也不证明现实数据。来源核验只覆盖固定资料库内的 CPI 和社会消费品零售总额环比材料，运行时不抓取开放网络；任意网页检索、RAG、CSV／手填来源、MCP、登录协作和公网部署留待后续阶段。阶段四任务 01、02、03、04、05 已实现在线验收（核心完成）：02 的 12 题配对评测（×2 臂 ×3 次，三轮）显示有检索臂主张状态正确率 91.3%、无检索臂 39.6%；03 把题集扩到 17 题并整组复跑五轮（每轮 17 题 ×2 臂 ×3 次），有检索臂 97.2%／90.3%／100.0%／96.8%／92.6%，无检索臂 29.7%／32.5%／43.5%／36.6%／20.8%；04 把题集扩到 19 题并整组复跑一轮（19 题 ×2 臂 ×3 次＋补证恢复段），有检索臂 90.0%（54/60）、无检索臂 30.5%，恢复段 3/3 通过且补充套用 3/3，q19 资料已覆盖 0 次追问；05 把题集扩到 20 题并整组复跑一轮（20 题 ×2 臂 ×3 次＋补证恢复段，计划 126 次请求），有检索臂 93.5%（58/62）、无检索臂 30.6%，60 次运行生成建议、69 处改动，模型 73 条改写提议里 31 条通过逐处校验被采用、42 条被拒并逐条留档，评测侧独立复算的新事实不变量在两臂 124 次有效运行里 0 次违规。虚构引用与无适用来源越界在这四批评测中均为 0，推断缺口、观点不做真假判定、「超过三条不静默丢弃」、先检索后追问、改动即失效与「建议不自动替换原配文」都有真实运行或浏览器证据。题型全部是开发题、没有预留题，不外推准确率；03 五轮上游失败 25%—50%（末尾确认是提供方余额耗尽），04 最终轮上游失败 0、但中途三轮因程序缺陷或审查修复（空 content 消息、`omittedClaims` 超限被整份拒绝、结论对照补漏配对主张）废弃重跑；主张分类准确率未单独统计，q11 出现过模型给配文主张补图上的比较方式，q18 追问率有漂移（04 有检索臂 3/3、05 为 2/3），加强表述拦截靠固定词表（实测出现的「略贵」不会被拦），这些都是仍然成立的局限。任务 06 的「官方修订／版本替代」已于 2026-10-01 实现并完成 22 题整组在线评测；「同口径冲突 → 来源存在分歧」仍因缺少适用来源对保留为 `needs-info`，不进入能力声明。本次维护修复了修订引用贯通、方向改写与补证隔离等缺陷；本地验证与尚未在线复验的边界见[项目审查报告](docs/reviews/2026-10-01-project-review.md)。
