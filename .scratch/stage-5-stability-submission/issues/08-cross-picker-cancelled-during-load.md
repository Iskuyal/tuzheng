# 08：主图载入完成前选对照图，选择会被静默取消

**What to build:** 主图仍在载入时，跨图区的对照图选择器不应接受选择后又被取消。要么在选择器可见时就不允许选（载入期间禁用），要么把选择排队到主图载入完成后再执行；无论哪种，用户都不该看到「选了下拉框又自己弹回去、且没有任何说明」。

**Blocked by:** 无

**Status:** completed（2026-09-30，实测见下方 Comments）

- [x] 复现路径固定为可重复的自动化用例：主图载入在途时选对照图，选择必须生效或给出明确提示，不得静默丢弃。
- [x] 选定一种语义（载入期间禁用选择器 / 排队后执行），并在规格或 ADR 中写明理由。
- [x] 主图载入失败或取消时，对照图选择器的状态与提示一致，不残留半配对状态。
- [x] 现有跨图用例在人为放慢主图接口的条件下全部通过（本任务记录中的 400ms 探针可复用为回归手段）。

## Comments

**2026-09-29 由 CI 首次运行暴露，诊断见下。本任务只记录问题，未改动产品行为。**

### 现象

PR #9 的首次 CI 运行中，66 条 e2e 有 4 条失败，全部是跨图用例，且分布不成规律（`143` 在 390 与 1280 失败但 320 通过，`163` 只在 390，`385` 只在 1280），耗时 4.3 分钟、约为本机（36 秒）的 7 倍。失败时的页面快照显示「选择对照图」下拉框仍停在占位的「选一张样例」，即选择没有生效。

### 证据

CI 的 Playwright trace 里，`/api/audit/sample` 只有两次请求：

| 顺序 | 请求体 | 结果 |
| --- | --- | --- |
| 1 | `{"id":"cross-a-revenue"}`（主图）| 200 |
| 2 | `{"id":"cross-b-conflict"}`（对照图）| **无响应，被中止（STATUS -1）** |

代码路径与之一致：`web/pages/AuditPage.vue` 的 `loadSample` 成功时调用 `setChartObservation`，而 `setChartObservation`（`:346`）会调 `resetCrossImageSession()`，后者经 `removeReference`（`:971`）执行 `cancelReferenceRequest()`（`:859`）——**主图载入完成时，会把仍在飞行中的对照图请求中止掉**。若这次选择发生在主图载入完成之前，用户的意图就被静默丢弃。

本机不复现的原因只是主图从 localhost 返回只要几十毫秒，快过 Playwright 发出 `selectOption`；CI 机器慢 7 倍，窗口就露了出来。

### 本地确定性复现

在 `server/app.ts` 的 `/api/audit/sample` 处理函数里临时注入 400ms 延迟（探针脚本用后即删，`server/app.ts` 已确认还原）：

- **修复前**（原用例）：24 通过 / **12 失败**，涉及 143、385、475、512、536、597 六条用例在多个视口的组合。
- **修复后**：**66 通过 / 0 失败**（同一 400ms 延迟，1.9 分钟）。

也就是说这不是 CI 环境的偶发问题，而是任何慢加载条件下都会出现的应用行为。

### 本次已做的处理（只动测试，未动产品）

给所有「导航后立刻操作跨图区」的用例补上「等主图载入完成」的断言（沿用本文件既有的 `.observation-form .title-field textarea` 断言写法），共 6 处：`e2e/reader-workbench.spec.ts` 的 143、163、385、456、512、625 行附近。这是正确的测试卫生——原用例在页面尚未就绪时就交互；但它**掩盖了产品侧的问题**，故单开本任务。

### 待定的产品语义

两条路，需要在规格或 ADR 里定：

1. **载入期间禁用对照图选择器**（推荐）：语义最直白，用户不会看到「选了又弹回」；实现上用一个「主图载入中」的状态绑定 `disabled` 即可。副作用是慢加载时跨图区短暂不可交互，需要确认这符合预期。
2. **排队后执行**：保留可操作性，但要处理载入失败、载入被取消、排队期间用户改选等分支，复杂度明显更高，收益不明确。

无论选哪条，都要覆盖「主图载入失败」时的选择器状态，避免留下半配对状态。

### 语义：载入期间禁用跨图区（不排队）

决策、备选、副作用与受影响分支写在仓库第一条 ADR [`docs/adr/0001-disable-cross-picker-while-main-image-loads.md`](../../../docs/adr/0001-disable-cross-picker-while-main-image-loads.md)。要点：

- 排队方案在**载入失败／被取消**分支无法自洽：没有新的主图观察值，执行排队项会把对照图配到**旧**主图上，丢弃又退回「操作了没有任何说明」；要补「排队中／载入失败已忽略你的选择」等状态才诚实。
- 载入期间跨图区本来也没有可比较的对象（`setChartObservation` 会清空配对，`crossCurrentClaimId` 直到新观察值落地才有效），放开选择器买不到任何可用比较。
- 禁用范围：选择／更换对照图下拉框、上传输入、「读取这张对照图」、「确认对照图读数」、两侧主张下拉框、逐要素「确认一致」。**「移除对照图」刻意保持可用**——它的效果不会被载入完成时的重置静默撤销。

### 产品改动

`web/pages/AuditPage.vue`（+29/−7）、`web/style.css`（+3）：

- 新增 `mainImageLoading`：在 `loadSample`（预置样例与 `?sample=` 载入）和 `analyzePendingUpload`（上传图的模型读取，超时上限 45 秒）中置位；在 `cancelImageRequest()`（唯一解锁点：换图、重新框选、取消读取、离开页面）与两个请求的 `finally` 中复位。并发载入按 `imageRequest === request` 判定，旧请求收尾不会误解锁新请求。
- 跨图区新增一行可见说明（`role="status"`）：「主图还在载入，跨图区暂时不能操作；载入完成后才能选择或更换对照图。」被锁控件补 `:disabled` 样式。

### 测试：新增 3 条 e2e（三视口共 9 条）

`e2e/reader-workbench.spec.ts`（+152 行；新增 `selectMainSample` 帮助函数：窄屏用 `#mobile-sample-select`、桌面用样例卡，两者都调同一个 `loadSample`）：

1. 「主图载入期间跨图区禁用并说明原因，载入完成后恢复」——`page.route` 按住 `/api/audit/sample`；载入在途断言说明文案、下拉框／文件输入／「读取这张对照图」禁用，放行后全部恢复且选择照常生效。
2. 「主图载入失败后跨图区恢复可用且不残留半配对」——前两次主图载入（请求的样例＋清单兜底那张）返回 503；断言失败后说明消失、选择器可用、无 `.cross-body`／对照图标签／半张比较表残留，之后选对照图仍能载入。
3. 「主图重新载入期间跨图区已配对的操作一并禁用」——先配对到 `conflict`，再按住一次主图重载；断言更换下拉框、两侧主张下拉框、逐要素「确认一致」、「确认对照图读数」全部禁用，而「移除对照图」保持可用；放行后跨图会话按既有语义重置、无残留。

**先红后绿：** 产品改动前，第 1、2 条在 320／390／1280 全部失败（**6 failed / 0 passed**，均卡在 `.cross-lock-note` 不存在，即旧代码里根本没有这个状态）；产品改动后 **9 passed**。
