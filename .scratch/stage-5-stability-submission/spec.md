# 阶段五规格：稳定性、固定评测与提交准备

Status: ready-for-agent

## Problem Statement

图证已能完成单图、多主张、跨图和纵轴核对，但参赛交付还缺固定评测集、对常见配置与服务故障的清楚恢复路径，以及可在另一台 Windows 电脑上复现的演示材料。2026-09-27 的真实模型复验中，用户把 Chat Completions 的完整接口地址填进 Responses Base URL，上传图片只得到通用 502；错误在保存时本可发现。

## Solution

以当前可靠的图内审计路径为核心，先防止可预见的设置错误，再扩充自制固定样例与独立期望，验证 API 不可用、输入无效和证据不足时的降级。交付文档、技术报告和演示视频只展示实际完成并验收的能力。阶段四来源核验仍是独立待办；阶段五可先完成不依赖它的稳定性工作，最终材料按阶段四的真实交付范围冻结。

## User Stories

1. 作为读者，我想在保存错误的模型接口地址时立即看懂哪里填错，以免上传后才遇到无说明的失败。
2. 作为读者，我想修正 Base URL 时保留已保存的模型名和 API Key，以免为了改地址再次提交密钥。
3. 作为读者，我想在模型不可用或输出无效时看到真实错误和下一步操作，以免误把预置观察当成模型结果。
4. 作为读者，我想在缺数字、缺证据或跨图口径不合时看到待确认，而不是确定的事实判断。
5. 作为开发者，我想用固定自制图、独立预期和重复运行的命令检查单图、跨图与纵轴行为，以便发现回归。
6. 作为团队成员，我想在新 Windows 环境按 README 安装并启动，以便演示不依赖某一台开发机的状态。
7. 作为评审，我想看见图片输入、模型观察、人工更正、确定性计算和证据如何接续，以便复查 AI 能力与边界。
8. 作为评审，我想获得可访问的仓库、完整运行说明、技术 PDF 和 5–8 分钟演示视频，以便审阅实际交付。
9. 作为团队，我想把“已本地通过”“真实模型通过”“待人工提交”分开记录，以便不把计划或替身测试写成已完成。
10. 作为读者，我想在保存设置之前测试当前地址、模型与密钥是否支持 Responses 结构化请求，以便及时修正配置，同时知道图片识别还需另行验证。

## Implementation Decisions

- 继续使用 Windows 根目录 Node/npm 启动方式；API Key 只经本机设置页交给回环服务，并保存在当前用户 LocalAppData，不改用环境变量或写入仓库。
- Responses Base URL 指服务根路径；应用自己追加 `/responses`。保存时拒绝明显的完整端点路径（例如 `/responses`、`/chat/completions`），给出可操作的错误，同时不改动原有设置。
- 「测试连接」使用当前未保存的表单参数；密钥栏留空时可沿用已存密钥，测试不写入配置文件。服务端只发一条有限时、有限输出的短文本 Responses JSON Schema 请求；成功只代表连接及结构化输出可用，不能替代图片读取验收。
- 固定样例沿用团队自制图片与独立预期，不把预置观察当成真实模型输出。目标总量至少 18 张；阶段四独有的来源核验样例待阶段四范围落实后加入。
- 错误提示明确区分未配置、连接失败、超时、结构不符、格式不支持与证据不足；失败不得生成新的确定结论。
- 稳定性记录使用仓库内 Markdown 和可重复的 npm 脚本；真实模型调用结果另记，不与替身或预置测试合并计数。
- 提交材料按仓库内赛题文档核对；公网在线演示为可选项，最终提交和需登录的赛事操作由团队人工完成。

## Testing Decisions

- 优先在现有 API 行为测试和浏览器端到端测试的最高可用接缝验证用户可见行为；不写仅重复条件判断的测试。
- 设置 URL 防错测试检查错误消息、原配置保持不变、有效服务根地址可保存，以及页面能显示服务端错误。
- 连接测试在服务端替身接缝检查请求契约、密钥选择、无持久化和失败分类；浏览器检查未保存表单参数、加载与成功/失败提示。真实模型结果另记，并与图片路径验收分开。
- 固定样例用独立期望覆盖一致、矛盾、待确认、口径不合和纵轴风险；测试应能发现人为引入的结论错误。
- 浏览器在 320、390 和桌面视口走代表性路径，检查错误恢复、证据边界与无横向溢出。
- 完整验收运行 `npm test`、`npm run test:e2e`、`npm run build`；涉及模型契约的真实调用单独记录端点、模型、样例、耗时与未验证范围，不保存密钥。

## Out of Scope

- 阶段四的来源核验、RAG、图文核稿与 CSV 导入的实现。
- 将用户手填或自带 CSV 自动评为可信外部来源。
- 用户登录、协作、数据库、默认公网部署及自动完成赛事最终提交。
