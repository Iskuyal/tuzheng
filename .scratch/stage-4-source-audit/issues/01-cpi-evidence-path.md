# 01：CPI 图文主张的公开来源核验闭环

**What to build:** 从团队自制 CPI 图表 PNG 与配文出发，经真实模型读取和受限工具选择，检索固定官方资料库，在页面展示可复查的来源结论与调用轨迹。

**Blocked by:** 无

**Status:** ready-for-agent

- [ ] 固定官方资料的原始 URL、发布机构、发布日期、适用月份／范围／比较方式、短摘录与内容指纹；加入至少一个错月份或错口径的干扰片段。自制图片和配文与官方原图、官方原文清楚区分。
- [ ] 新图文观察结构接受没有明确增长率标题、但有 CPI 数值和配文比较方式的输入；缺失信息保留为空，旧 `claims[]` 路径与样例保持原有行为。
- [ ] 本机 Responses 服务端声明受限 `function` 工具，模型可选择检索、预定义数值比较或请求确认；校验工具名、参数、调用次数、超时和返回体。记录模型实际调用与程序执行结果，不用固定顺序或预设案例 ID 伪装模型决策。
- [ ] 图文主张按指标、月份、地域／人群、同比／环比与来源片段对齐；只把适用的官方发布用于数值核对，定义页只用于解释术语。引用不存在或不适用时降级为「来源待核对」。
- [ ] 页面可从上传图与填写配文走到结果，分别展示图内观察、配文、官方来源、工具轨迹、引用和未解决项；没有密钥时给出可操作提示。保留现有单图与跨图路径。
- [ ] 本地行为测试和浏览器端到端测试覆盖完整路径与一个来源不适用分支；`npm test`、`npm run test:e2e`、`npm run build` 通过。
- [ ] 用当前真实模型单独验证图片读取、真实工具调用和检索结果；若具体模型不支持工具调用，记录证据并调整可配置模型或保持任务未验收，不把替身通过计为在线通过。
- [ ] 按实际验证更新阶段四任务、路线图和 README 的能力状态，不提前标为已交付。
- [ ] 工具轨迹展示实际事件及简短行动理由，每轮最多三次、单次调查总计最多六次调用；所有失败与停止可见。首片完成单主张，后续拆解、恢复和修改建议按依赖顺序加入。
