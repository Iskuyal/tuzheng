# 04：补充关键信息并恢复调查

**What to build:** 模型提出一个会影响当前主张的关键问题，用户补充后恢复核验；现场改月份或范围能让旧结论立即失效。

**Blocked by:** 03：拆解短配文并检查推断依据

**Status:** completed（已实现、已在线验收 2026-09-29）

## 交付内容

- **追问更具体**：`request_clarification` 增加 `claimText`（逐字引用受影响的主张），提示词把追问从「可以问」改为硬性要求——先自己检索，检索后仍缺会影响结论、而资料库回答不了的口径（例如配文没写比较方式、而同比与环比发布都在库里）时必须提一个具体问题，并禁止拿数值相等自行认定口径。
- **补证数据结构与纯函数**（`shared/source-audit.ts`）：`parseClarificationAnswer`（同比／环比、YYYY-MM、数值、范围／指标的解析，解析不了就不套用）、`applySupplementToClaims`（图文没写才填入并标为用户提供；已写且一致不改；已写但冲突时不覆盖、恢复图文值并保留双方）、`applySupplementToConclusion`（冲突降为「来源待核对」并同时列出图上／配文侧与用户侧内容、请求更正）、`diffConclusions`（补证前后逐条状态对照与原因）、`resolveSupplementTarget`（追问没指明主张时只在唯一缺口主张上回退）。
- **恢复编排**：`runSourceInvestigation` 新增 `resume` 选项——驱动器在同一段对话上注入用户回答（Anthropic／Responses 都先补齐未回应工具调用的配对结果，否则整段对话被 HTTP 400 拒绝）；预算共享：调用数、轮次与追问次数从补证前结果接续（追问已用满则恢复段再追问被拒、轮次用满则不再执行工具直接带补充强制汇总）；检索命中随会话带入但引用与结论按本轮主张口径重新校验，不沿用 prior 结论；结果带 `supplement`（问题、回答、解析、冲突）与 `conclusionChanges`（前后对照与原因）。
- **API**：`investigate` 签发 `investigationId`（图片+配文 SHA-256 指纹）并保存可恢复会话（`server/source-sessions.ts`，TTL 30 分钟、上限 16 条、过期即淘汰）；新增 `POST /api/source-audit/resume`——会话过期或不存在 410、输入指纹失配 409（改动即失效）、没有待回答追问 409、缺回答／缺 ID 400；恢复沿同一记录同一段对话续跑，失败映射与初查共用且不附带结论。
- **页面**：追问区新增回答入口（标为「用户提供」）；补证记录、冲突双方、结论前后变化逐条展示；新增「历史结论（仅作历史展示）」区块，重新核验／改配文／换图／补证接续都把旧结论移入历史并标原因；请求序号令牌 + AbortController 实现在途隔离——输入改动或取消即作废在途请求，迟到响应直接丢弃，不复活旧结论。
- **固定评测扩展**：17 → **19 题**（q18 必要追问＋补证后改判、q19 资料已覆盖禁止追问），`clarifyAnswer`（用户回答，输入侧）与 `resume` 期望（补证后规则）先于任何模型运行写定；新增 `clarificationRequired`／`clarificationAfterSearch`（有检索臂追问必须发生在检索之后）／`clarificationForbidden`／`supplementApplied` 判定；runner 两阶段：初查提出追问才沿同一 driver 恢复、两段各自判定并落记录，未追问时不编造补证后记录；02 的 12 题与 03 的 5 题整体哈希新增校验和守护；`omittedClaims` 上限由 6 放宽到 30（附属列表超限不该丢弃整份汇总），结构被拒后的重报指令带具体错误摘要。
- 证据记录：[`docs/evidence/stage-4-source-audit-clarify-resume-2026-09-29.md`](../../../docs/evidence/stage-4-source-audit-clarify-resume-2026-09-29.md)，逐次运行记录同目录 `stage-4-source-audit-eval-2026-09-29-clarify-resume.json`。

## 验收结果（真实模型整组一轮，19 题 × 2 臂 × 3 次 + q18 补证恢复段 = 计划 120 次请求）

| 门槛 | 结果 |
| --- | --- |
| 有检索臂主张状态正确率 ≥ 80% | **PASS** 90.0%（54/60 次有效运行） |
| 虚构引用为零（两臂） | **PASS** 0 条 |
| 无适用来源案例不下确定来源结论（两臂） | **PASS** 0 次越界 |

- **必要追问案例（q18，有检索臂）**：3 次初查全部先检索再动作（`clarification-before-search` 0 次）、3/3 提出指向配文主张与 basis 的追问并完成恢复——`conclusionChanges` 显示配文主张 `source-pending → source-match`、原因「用户补充确定了比较方式」；恢复段补充套用 3/3，预算累计接续（例：初查 2 次 + 恢复 1 次 = 3 次、轮次累计至 4 后强制汇总）；配不上对的主张也单列出行（恢复后未再汇报／补证后新增），不静默丢弃。
- **无需追问案例（q19，有检索臂）**：0 次追问（`clarificationForbidden` 守住，两臂合计 0 次 unexpected-clarification）；3 次中 1 过、2 未过（no-matching-claim、no-conclusions，见局限）。
- 有检索臂原 17 题（补证前）单独统计 47/51 = 92.2%；引用接受 121 条、被拒 3 条全部带原因、虚构0；配对差 59.5 个百分点，检索臂退化题 0。
- 无检索臂 30.5%（18/59），与 03 同区间；无检索臂恢复段 2 次补充套用成功但拿不到引用，记 wrong-status，不进门槛。
- 最终轮上游失败 **0**、汇总结构被拒 **0**；开跑余额 1.89 元、收尾 1.03 元（本轮实耗约 0.86 元）。

## 未达标与局限（逐条记录，不删题）

- q18 追问率有检索臂 3/3、无检索臂 2/3——提示词行为仍有漂移；未追问（无检索臂 1 次）判 `missing-clarification` 未通过、补证后阶段不运行，不外推为稳定能力。
- q19 有检索臂 1/3 通过：#1 记 no-matching-claim（模型拆出的主张与冻结 select 不匹配）、#3 记 no-conclusions（未给出有效汇总）——开发题、小样本，不删题不回填。
- 补证恢复的在线样本只有 5 次（有检索 3、无检索 2），不足以给出恢复段的稳定比率。
- 无检索臂 q19 3/3 未通过（拿不到引用，既有两臂设计）；无检索臂 q18 恢复 2 次因同样原因记 wrong-status。
- q11 有检索臂 2/3 未通过（模型给配文主张补了图上才有的比较方式，03 已记录的既有局限）。
- Responses 协议的工具循环与恢复段配对补齐仍只有替身测试；会话过期、指纹失配、重复补证、取消与迟到响应由替身与浏览器测试覆盖，未在线复验。
- 补证回答解析只覆盖常见写法，口语化回答记为无法解析且不套用（有单测）。
- 中途三轮废弃（空 content 拒绝、`omittedClaims` 超限被整份拒绝且重报不带错误、审查修复 `diffConclusions` 后作废重跑），修复与审查过程见证据文档第三节，都有单测守护。

- [x] 资料已经覆盖的问题先检索；仍缺信息时提出一个具体问题，说明它影响哪条主张及哪项口径，不要求用户代找已有材料。
  - 提示词改为硬性要求＋`claimText`；q18 有检索臂3 次初查全部先检索再动作（0 次 clarification-before-search）、2 次提出指向配文主张与 basis 的追问；q19 3/3 先检索不追问。
- [x] 每次调查最多一轮补证追问，补证仍不充分时停止并列出未解决项；前后共享总调用预算，不能通过恢复清零预算。
  - 追问次数、调用数、轮次均从 prior 接续：恢复段再追问被拒（单测）、轮次用满直接带补充强制汇总（单测）、实际恢复段预算累计（线上 q18 例：2+1=3 次、轮次至 4 强制汇总）；补证解析失败不套用并写明原因、冲突降为待核对（单测）。
- [x] 用户回答标为用户提供，只帮助确定口径；不能覆盖明确的图文内容或自动变成官方证据。存在冲突时保留双方依据并请求用户更正输入或保持待核对。
  - `applySupplementToClaims`／`applySupplementToConclusion`：没写才填入并标「用户提供（不是官方来源）」，冲突不覆盖、恢复图文值、降为待核对并列双方、请求更正（单测＋API 冲突测试＋页面展示）。
- [x] 补证前后关联同一主张与记录，可看到检索条件和结论为什么改变；不能自动沿用不再适用的旧引用。
  - 同一 `investigationId`、同一段对话、同一轨迹（恢复段带 prior 轨迹，线上可见 search→clarify→report 全过程）；`conclusionChanges` 逐条给 before/after 与原因（线上实测 pending→match）；引用按本轮主张口径重新校验、不沿用 prior 结论（单测「恢复段沿用检索命中但引用重新校验」）。
- [x] 修改图片、配文、月份、范围或比较方式后，受影响结论立即失效；取消、重置和旧响应迟到不得恢复旧结论。历史结果明确标为历史。
