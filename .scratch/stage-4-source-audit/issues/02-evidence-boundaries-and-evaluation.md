# 02：证据不足分支与检索增益评测

**What to build:** 沿 CPI 图文主张路径增加来源缺失、口径不合、模糊图和工具失败分支，并用固定问题集证明检索是否改善有证据支持的判断。

**Blocked by:** 01

**Status:** 已实现、已在线验收（2026-09-29）

## 交付内容

- 固定题集 **12 题**，输入与独立期望分开保存：`samples/source-audit-questions.json`（图片、配文、图上声明文字、SVG／PNG 双指纹）与 `samples/source-audit-expectations.json`（判定规则、必需引用、允许状态、门槛、冻结配置）。覆盖数值正确、同比与环比错用、错月份、错范围与人群、图上比较方式不明、资料库无适用来源、干扰来源命中。
- 题集用图 5 张，团队自制并标明「不是国家统计局原图」：既有 `cpi-2025-12`，新增 `cpi-2025-12-yoy`、`cpi-2025-12-mom`、`cpi-2025-12-city`、`cpi-2026-08-yoy`（生成器 `samples/make-cpi-eval-charts.mjs`）。
- 无检索臂：服务端把 `search_source_library` 从工具声明里移除，编排层同时拒绝任何检索调用（不执行检索、不回落命中），并要求模型把缺少可用来源写进 `noApplicableSourceReason`。
- 评测入口 `npm run eval:source-audit`（独立于 `npm test`，会调用真实模型）：运行前对图片指纹、资料库指纹、预算常量、类别覆盖、协议与模型做冻结检查，任何一项不符即停止；支持 `--runs`、`--arms`、`--ids`、`--record`、`--strict`。
- 结果与逐题证据见 [`docs/evidence/stage-4-source-audit-evaluation-2026-09-29.md`](../../../docs/evidence/stage-4-source-audit-evaluation-2026-09-29.md) 与同目录的逐次运行记录 JSON。

## 本轮由固定题集暴露并修复的两处程序问题

1. `concludeClaimSource` 与 `validateCitations` 原先都按**检索查询**的口径判断引用是否适用；同一次调查会按多个口径检索，命中资料对某条主张是否适用与查询口径无关。现改为按**主张自己**的指标／月份／范围判定，命中内但与任何主张口径都不符的引用才进入「被拒绝的引用」并给出月份／范围等原因。
2. 第 B 轮真实运行出现「模型引用了正确月份的 2026-08 发布，却被程序按查询口径拒绝」；修复后第 C 轮该题 3/3 通过。第 A、B 轮的 90.9%／91.7% 属修复前，不与第 C 轮相加当作同一程序的成绩。
