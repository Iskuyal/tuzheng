# 分享来源核验结果

日期：2026-11-10（第二轮补充：三档分享格式）。依据 [PLAN](../../PLAN.md)（第 25 行「再将解释分享给朋友」、第 82 行导出页「不把模型建议写成事实结论」）、[领域术语](../../CONTEXT.md)（主张、来源结论、引用角色、未解决项、历史结论、修改建议）与本次用户要求。

## 一条用户路径

已有一份**当前有效**的来源核验结果 → 在结果区点「分享这次核验」→ 弹层显示「分享格式」三选一（①文字 ②图片 ③文字+图片）→ 默认「文字」；选「图片」时现场画出一张竖版长图（1080 宽 PNG），可「下载图片」或「复制图片」；选「文字+图片」时两种同时给，文字可复制、图片可下载或复制 → 按 Escape 关闭弹层，焦点回到触发按钮。

三档都来自同一份摘要正文（`web/source-share.ts` 的 `buildShareSummary`）：图片是这段文字的排版截图，因此文字里有的边界声明、结论、引用来源、未解决项、指纹在图片里同样存在，不会出现「图片版更松」的口子。

## 图片档的具体约定

- 画布 1080 像素宽、内边距 72、高度按内容自适应（最小 640），最长边上限 12000；超出时截断正文并写明「摘要过长，图片只显示到这里；完整文字请用『文字』或『文字+图片』分享。」，不假装图片是全的。
- 首行 `图证 · 来源核验摘要`（衬线、48px），紧跟一行边界声明原文（26px 灰），结尾仍是 `摘要指纹：` 加 16 位十六进制（等宽、琥珀色）与指纹说明行；指纹行不是最后一行。
- 折行时收尾标点跟随上一行（悬挂标点），避免出现只剩「。」的一行；子行按原文缩进对齐，不回到顶格。
- 图片文件名由摘要正文指纹推出：`图证-来源核验摘要-<8位十六进制>.png`，同一份摘要永远同名，不同摘要不会互相覆盖。
- 图片只存在于浏览器内存与用户自己的磁盘／剪贴板：不生成服务端短链，不经第三方图片托管，不新增后端路由。

## 验收

- 320／390／1280 视口：结果区入口与弹层可用、无横向溢出；三档切换后预览、按钮与说明都不折行、不被遮挡。
- 真实 Tab／Enter／Escape 完成打开 → 切换格式 → 复制／下载 → 关闭；打开后焦点落在格式单选组，方向键可切换档位；关闭后焦点回到触发按钮。
- 剪贴板不可用时降级可用：文字档不报「已复制」，改为选中摘要文本并提示 Ctrl+C；图片档不报「已复制图片」，提示改用「下载图片」。
- 摘要是纯文本、确定性生成：同一份结果重复生成逐字相同；图片文件名与摘要一一对应；单测覆盖折行、悬挂标点、缩进、截断提示与文件名（`tests/source-share-image.test.ts`）。
- 口径：边界声明原文同时写进文字与图片；模型修改建议只标为「尚未采用」的参考；用户补充的口径值标为「用户提供」，不是官方来源。
- `npm run typecheck`、`npm test`、`npm run docs:check` 通过，`e2e/source-share.spec.ts` 通过。所有模型路径离线拦截／替身，真实模型调用为 0。

不做服务端短链、不做第三方图片上传，也不把分享结果回写数据库。读屏软件实际朗读、真机、系统级剪贴板权限（`clipboard.write` 需要安全上下文与用户授权）、以及「接收者据此相信摘要」都不由本次离线证据证明；图片里的指纹同样只证明文字未被改动，不防伪造。
