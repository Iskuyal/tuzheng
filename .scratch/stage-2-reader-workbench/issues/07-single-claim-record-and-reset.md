# 07：单主张路径也提供会话记录与整份重置

**What to build:** 读者在阶段一那三个单主张样例（以及模型只读到一条主张的图片）上，也能看到本次会话里的确认与更正记录，并一键重置回最初载入的读数。

**Blocked by:** 03、06 — 均已完成

**Status:** completed

- [x] 单主张表单提供与多主张相同的记录：动作（更正读数／确认并计算／重新计算）、发生变化的值、对应结果与时间。
- [x] 同一字段连续输入合并为一条更正；没有真正改变数值的输入不记事件——与多主张路径同一套规则，不另写一份。
- [x] 表单上方提供「重置本次审计」，恢复当前图片最初载入的观察值并清空结果与记录；计算在途时禁用。
- [x] 记录只在当前会话，切换图片、刷新后不保留；不写浏览器存储、本机文件或服务端。
- [x] 记录列表的标记与多主张共用同一个组件与样式，不复制一遍。
- [x] `npm run test:e2e` 在三个视口断言：确认后记录出现；更正后记录含变化值；重置后读数恢复、结果与记录清空。

## Comments

**2026-09-26 实现与实测：**把记录规则从工作区里抽成两个可复用原语 `recordCorrection` / `recordReview`，并把**编辑语义**抽成 `applyClaimEdit`（`shared/claim-workspace.ts`）：数值归一化、「数值没变就不算更正」、清空时标为不可读、改动时标为用户更正都只写一次，两条路径共用。多主张工作区的 `updateClaimDraft`、`completeClaimReview` 与单主张表单都调用这份实现——两轴代码审查指出过，光抽记录原语还不够：单主张原本在数值没变时也清结论、也把来源标成用户更正，与多主张不是一套规则，现已统一。记录列表的渲染抽成 `web/audit-record-rows.ts`（行构造与文案）加 `web/components/AuditRecordList.vue`（标记），两条路径共用；页面里重复的状态标签函数也一并收进模块。

单主张路径新增：载入时保存初始观察快照、按字段记录更正、确认时记录 confirm／recompute 与结论；表单顶部是与多主张同样的「记录只保留在本次会话」和一键重置（`AuditSessionBar` 组件，两条路径共用文案与样式），重置从快照恢复读数并清空结果与记录（计算在途时禁用）。切换样例、重新载入和刷新都会清空；每次编辑、重置与换图都会推进一个会话修订号，计算在途时若换图或继续编辑，迟到的响应不写回结论也不追加记录（与多主张路径按工作区身份判定的守卫等价——那条路径靠不可变更新，这条靠修订号）。

实测（320／390／1280 三个视口）：确认后记录出现「确认并计算 → 图内矛盾」；把较早数值重新输入成同一个 80 时结论与记录都不变；改成 90 后记录出现「较早数值 80 → 90」且结论被清除；只改单位也记一条「较新单位 万元 → 元」；重置后标题回到 40%、两个数值回到 80／100、记录与结论清空、按钮回到禁用，之后再确认仍得到 25% 与「图内矛盾」。另外在浏览器里延长响应时间验证在途行为：计算中继续编辑或切换样例，迟到的响应都没有写回结论或记录。`npm test` 为 53/53 通过（含编辑语义与记录原语的直接用例），`npm run test:e2e` 6/6，`npm run build` 通过。

至此阶段二规格里「记录确认、更正、重算和结果变化」与「一键重置整份审计」在单主张与多主张两条路径上都成立，issue 03 当初记下的「未做」项关闭。
