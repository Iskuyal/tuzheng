## Comments

**2026-09-26 实现与实测：**新增 `@playwright/test` 作为开发依赖、根目录 `playwright.config.ts` 与 `e2e/reader-workbench.spec.ts`，入口是 `npm run test:e2e`。测试只走预置示例，不需要 API Key；配置里 `webServer` 用 `npm run dev` 起前后端（已在本机运行的服务会被复用），并固定使用系统自带 Edge（`channel: "msedge"`），无需额外下载浏览器。视口项目为 320×640、390×844，另加一条 1280×900 回归防线（原因见下）。

两条用例：多主张样例走完查看证据、确认收入、更正利润、补入用户数再核对、查看审计记录、一键重置、重置后重新核对的完整路径，并断言更正利润不影响收入结果、缺依据的用户数主张始终为「需要确认」、重置把较新值恢复为预置的 70；阶段一样例走确认与计算，并检查操作区不重叠。两条用例都断言：页面无横向溢出（`scrollWidth ≤ clientWidth + 1`）、确认按钮与重置按钮高度 ≥ 40px、核对数值输入框最窄 ≥ 56px。

实测：`npm run test:e2e` 在冷启动（没有预先运行的服务）下 **6/6 通过**，约 9 秒；单独跑 320px、390px 各两条也都通过。为确认测试不是空跑，做了两次变异验证：把 `resetClaimWorkspace` 改成不清空记录后，重置断言失败；把主张卡按钮的 `width: 100%` 与间距覆盖删掉（恢复缺陷状态）后，1280px 项目的操作区重叠断言报出 `buttonHintOverlap = 6`，正是当初截图里那 6px 重叠。这两次变异都随后回滚，当前工作树与测试均为通过状态。

`npm run typecheck` 增加了 `tsconfig.e2e.json`（Node + DOM 类型），让 e2e 代码也进入类型检查；它当场发现并修掉了一处 `NodeList` 展开缺 `DOM.Iterable` 的问题。

**未覆盖：**真实云端模型读取（那属于 `docs/STAGE-1.md` 的复验步骤，且需要密钥）；上传、框选、放大弹层在窄屏下的交互；真机移动浏览器的字体与触摸行为。本测试是本地预置示例的浏览器验收，不代表在线模型结果。
