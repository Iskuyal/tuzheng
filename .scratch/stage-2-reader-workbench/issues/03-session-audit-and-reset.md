# 03：增加会话审计记录和整份重置

**What to build:** 读者可以查看当前审计会话中各项主张的确认、更正和重算记录，并在需要时清除本次状态。

**Blocked by:** 02：完成逐条确认、更正和局部重算

**Status:** completed

- [x] 操作记录显示主张、动作、发生变化的值和对应结果，便于回看每项结论如何形成。
- [x] 记录只保存在当前会话，不写入浏览器存储、本机文件或服务端持久存储。
- [x] 重置操作恢复当前图片最初载入的观察值，并清除所有确认、更正、结果和会话记录；模型设置页保存的配置不属于本次审计。（记录与重置落在多主张工作区路径；阶段一单主张表单不建立工作区，因此没有记录与重置入口。）

## Comments

**2026-09-26 实现与实测：**记录保存在 `shared/claim-workspace.ts` 的 `ClaimWorkspace.events`，事件含发生时间、主张标识、主张原文、动作（`correct` / `confirm` / `recompute`）、发生变化的值和对应结果；确认动作区分首次确认与再次重算。用户在同一个字段上连续输入（数字输入框逐字触发 `input`）会合并成一条更正记录，保留最初的旧值，时间取该字段最后一次输入；中间发生确认或换到别的字段、别的主张时不合并。没有真正改变数值的输入不记事件，也不清掉已有结论；逐字输入又回到原值时那条记录会被撤回（净变化为空）；把字段改成别的值再改回来时，结论仍需重新确认，因为期间的输入确实不同。

界面在主张列表上方给出「记录只保留在本次会话」和一键「重置本次审计」（无记录或正在计算时禁用），每条主张卡内以可折叠列表展示该主张的记录；出现结果变化时标出「此前为 …」，更正后清除结论的事件标「原结论已清除，等待重新确认」，从未确认过的只标「等待重新确认」。重置由 `resetClaimWorkspace` 从最初载入的原始观察重建草稿值，清空确认值、确认状态、结果和全部记录。计算请求在途时按工作区身份判定是否写回，重置或换图之后的迟到响应不会把结果写回。

实测（Edge/Chromium，1440 与 320px）：确认主张 1 记录「确认并计算 → 图内一致」；主张 2 输入 100 只留下一条「更正读数 较新数值 70 → 100」；更正主张 1 标题再确认后记录里出现「图内矛盾（此前为 图内一致）」；主张 3 无记录。在途请求期间重置按钮和确认按钮都禁用，请求返回后记录正常追加；在途请求遇到样例切换时不产生错误提示，也不留下结果。点重置后主张 1 标题回到 25、主张 2 较新值回到预置的 70、三条主张都回到「待核对」、结果与记录清空，重置按钮回到禁用，随后可重新核对。切换样例、重新载入同一张样例和刷新页面后记录均为空；操作前后 `localStorage` 与 `sessionStorage` 条目数都是 0。`npm test` 为 47/47 通过，`npm run build` 通过。
