# 05：让模型读取过程在界面上可见

**What to build:** 读者和评委能在页面上看到这次识别实际发生了什么：用了哪个模型、花了多久、发了什么、模型原样返回了什么，以及校验后才生成的观察值。

**Blocked by:** 无（03 完成后按用户要求插入）

**Status:** completed

- [x] 上传读取后，核对区顶部显示本次读取的模型名、耗时、发送内容（整张图片或框选区域）与字节数、token 用量。
- [x] 可展开查看模型原始返回文本，并写明它只是未经校验的原始输出，观察值与来源标记由程序校验后生成，模型不返回确认状态、计算值或结论。
- [x] 预置示例不显示该面板，也没有对应的模型读取轨迹，避免把预置数据说成模型读取。
- [x] 轨迹只存在于当前会话内存：不写浏览器存储、本机文件或服务端持久存储，不包含 API Key 或端点地址。
- [x] 自动化测试覆盖接口返回的轨迹字段、预置样例不含轨迹、适配器返回原始文本与 token 用量。

## Comments

**2026-09-26 实现与实测：**`VisionAdapter.extract` 从“只返回解析后的 JSON”改为返回 `{ observation, model, requestId, usage, rawText }`；服务端在 `/api/audit/image` 里测量耗时与图片字节数，与模型返回的模型名、响应 id、token 用量一起作为 `ModelReadTrace`（定义在 `shared/audit.ts`）随响应返回。接口只在成功时返回轨迹：结构校验或请求失败时返回原来的错误分支，页面不显示面板。日志文本、token 用量和响应 id 都不含密钥，密钥仍只在服务端与用户配置文件中。

界面在核对区顶部加一条「模型读取过程」：首行常显模型名、耗时、发送内容与大小、输入/输出 token；下面可展开「模型原始返回（未经校验）」，配一句说明它通过结构校验后才生成下方观察值。切换样例或换图后轨迹清空，同一张图重新读取会替换为新轨迹。

实测（真实模型，非替身）：上传 `unclear.png` 后显示出 `deepseek/deepseek-v4.1-flash`、耗时 3.8 秒、发送整张图片（25 KB）、输入 849 / 输出 380 tokens，展开可见模型原始 JSON 里 2025 年数值为 `null` 且带两条 `unreadableItems`，页面下方核对表的较新数值显示「图上暂不可读」；320px 视口面板不溢出、原始返回自动换行、无横向滚动。`npm test` 为 49/49 通过，`npm run build` 通过。

**边界：**这里是**单次模型读取**的轨迹，不是多步骤 Agent 的工具调用轨迹；后者（读图 → 判断缺什么 → 请求确认 → 调用计算器）属于阶段四的受控工作流，本任务不做。轨迹只在浏览器内存里，刷新即消失；如果要留下可回放的演示记录，需要另开任务（并明确它属于持久化范围）。
