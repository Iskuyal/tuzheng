# 阶段二规格：读者工作台完善

Status: ready-for-agent

## Problem Statement

目前一张图只审计一个增长率主张。读者无法在同一工作台中逐条核对多项说法，也难以确认更正某个读数后是否意外改变了其他结论。现有单项结果没有当前会话内的操作历史，缺证据时也需要逐条保证不会误显示确定结论。

## Solution

在单张图的审计会话中使用 `claims[]` 表示多项可核对主张。预置数据或视觉模型只提供主张原文、图上观察、图内证据和无法辨认项；工作台再为每条主张独立保存用户确认或更正值、确认状态和由程序计算的结果。读者可以逐条查看、确认、更正和重算；更新一条主张只改变该主张，不改变其他主张的输入、确认状态或结果。

当前阶段继续使用已有的增长率规则。每条主张的图内依据和确认值足以计算时，显示“图内一致”或“图内矛盾”；缺少与读数对应的图内依据、必要数字或有效时间顺序时，保持“需要确认”，不输出确定结论。图内标签位置存在但数字模糊时，用户补入并确认读数仍可按阶段一既有规则计算，结果须标出用户更正。

主张卡区分未确认的图内观察、用户确认或更正的图内读数、以及缺失或不可辨认的图内证据，并另行标明数据来自预置示例还是视觉模型。这些标签只说明图内证据的状态，不评定外部来源可信度。

系统在当前审计会话中记录确认、更正、重算和结果变化。记录只保存在当前会话内。重置审计会清除更正值、确认状态、结果和操作记录，并恢复当前图片最初载入的观察值；切换图片、刷新或离开会话后不保留记录。

阶段二开发和验收使用明确标为“预置示例”的团队自制数据，不把它描述成真实模型输出。阶段一已有的三个单主张样例继续可用，新增一张三主张样例。结构化输出校验应适配 `claims[]`，但没有真实 API Key 时不声称在线 Responses 调用通过。以后获得密钥后，仍需对阶段一记录的三个样例执行真实读取和结构化输出验收。

## User Stories

1. 作为只有图表截图的读者，我想在一张图上看见多条可检查主张，以便一次审阅完整图文内容。
2. 作为读者，我想逐条查看每项主张对应的原始观察和图中文字证据，以便知道判断来自哪里。
3. 作为读者，我想确认一条主张而让其他主张仍保持待核对状态，以便分开完成审阅。
4. 作为读者，我想更正单条主张读错的数字，并保留原始观察，以便知道更正前后分别是什么。
5. 作为读者，我想只重算受更正影响的主张，以便其他已完成结果不被覆盖或重置。
6. 作为读者，我想在证据缺失或数值无法辨认时仍看到“需要确认”，以便不把猜测误当成结论。
7. 作为读者，我想查看当前会话里对每条主张进行的确认、更正和重算记录，以便复查判断变化。
8. 作为读者，我想一键重置当前整份审计并清除记录，以便重新开始而不留下混合状态。
9. 作为手机用户，我想在窄屏上逐条查看证据、确认或更正并看到结果，以便不需要切换到桌面设备。
10. 作为读者，我想清楚知道数据来自预置示例还是模型读取，并看到图内结论的边界，以便不把预置数据或图内一致性当作现实数据核验。
11. 作为读者，我想区分未确认观察、已确认或更正的读数和缺失证据，以便理解每条结论的依据与限制。
12. 作为已使用阶段一样例的读者，我想继续使用原有三个样例并得到相同的图内结果，以便阶段二不会使原有路径失效。

## Implementation Decisions

- 一张图片拥有一个审计会话。预置样例和视觉模型的 `claims[]` 仅提供每项主张的原文、图上观察、图内证据和无法辨认项；模型不提供用户确认值、计算结果或结论。
- 工作台为每条主张建立稳定标识和独立审计状态，保存适用的增长率规则、用户确认或更正值、确认状态及程序计算的结果。
- 原始图上观察与用户确认值分开保存。证据摘录保持与图片对应，不因更正数值而被覆盖。
- 每条主张分别展示图内观察的提取或预置来源、用户确认或更正状态，以及证据缺失状态；它们不等于外部来源可信度评分。
- 主张各自拥有自己的观察快照；当前阶段不建立跨主张共享读数或依赖图。某项更正只影响所属主张。
- 只有当前已有的增长率检查规则进入阶段二。结果仅分为“图内一致”“图内矛盾”和“需要确认”；本阶段不新增“可能误读”规则。
- 保留阶段一的三个单主张样例和对应预期结果；它们可作为仅含一项的 `claims[]` 继续运行。新增的团队自制验收图包含三条独立主张：收入 80→100、标题写 25%；利润预置观察值 50→70，但图片上的 2025 年利润文字为 100、标题写 40%，供读者将预置的待更正读数改为 100；用户数旧值为 50，图内没有新值对应依据，标题写增长 20%。完成逐条确认和更正后，三项结果分别为图内一致、图内矛盾和需要确认。预置的误读不冒充真实模型输出，样例图与独立预期结果须一致。
- 严格校验 `claims[]` 的结构，拒绝字段形状错误的输出。无法辨认的值或证据可以为空，属于有效观察并进入“需要确认”；有效的空数组应提示没有发现可核对主张，不生成虚构结论。样例可在没有 API Key 时运行；阶段二不依赖真实云端调用。
- 会话记录包含发生时间、主张标识、确认或更正动作、发生变化的值以及对应结果。记录仅存在于当前会话；重置会同时恢复初始观察值并清空整份记录。
- 跨图比较、真实来源核验、原始数据导入和持久化历史不属于阶段二。

## Testing Decisions

- 自动化行为测试检查每条主张的增长率计算、三类结果、确认值与原始观察的区分、主张之间的状态隔离，以及缺少图内依据时即使手填数字也不产生确定结论；同时确保阶段一“看不清”样例在用户补值后仍可得到原有结果。
- 服务端结构验证和样例 API 测试区分“结构错误”与“数值或证据无法辨认”，并覆盖有效空数组、预置来源标记和新旧样例；这些测试不模拟成真实在线模型通过。
- 自动化浏览器测试驱动同一张三主张样例完成逐条核对、更正、查看操作记录和重置；在 320px 与 390px 视口检查核心操作可用且页面没有横向溢出。
- 沿用当前纯增长率计算和 API 结构校验测试边界，并补充可重复的浏览器端到端测试。完整验收无需 API Key。

## Out of Scope

- 跨图或图文之间的比较。
- 对现实数据或外部来源进行核验。
- 数据库、本机文件或浏览器存储中的持久化审计记录。
- 新的计算规则、RAG、用户登录、协作或公网部署。

## Further Notes

阶段一的本地功能验收已通过，但独立 UI 评审最近得分为 8.4/10、9/10 门槛仍未达成，真实 Responses API 调用也未验证。阶段二可独立使用预置示例开发；阶段一的两个未结项继续保持未验收。获得真实密钥后，用阶段一记录的三张 PNG 验证在线读取，并按迁移后的 `claims[]` 结构核对各图中相关主张，不沿用旧的单对象响应形状。
