# 02：第二张图、口径配对与确认

**What to build:** 读者能把第二张图放进同一次核对，看到系统给出的候选配对与口径四要素，并逐项确认。

**Blocked by:** 01

**Status:** completed

- [x] 同一次会话可放第二张图（样例或上传），标注为「对照图」，切换或移除它不影响当前图的确认状态与结果。
- [x] 系统按指标名给出候选配对（去空白、全半角、大小写后相等），并在界面上展示两侧的指标、时间、单位、范围。
- [x] 四要素齐备且一致时才能进入比较；任一缺失或不一致时显示「待核对」并列出差在哪个要素。
- [x] 用户可对单个要素点「确认一致」补上读不出的信息，确认留痕且只影响本次会话。
- [x] 对照图未确认的读数不参与比较，保持「待核对」。
- [x] 自动化测试覆盖配对归一化、四要素三种走向与「未确认不比较」。

## Comments

**2026-09-26 实现与实测：**新增 `shared/cross-image.ts`（纯函数）：口径标签归一化 `normalizeLabel`（NFKC + 去空白 + 小写）、按指标名挑选候选对照主张 `pickReferenceClaimId`、四要素比对 `compareClaimScopes`（返回逐要素状态与阻塞项，并区分 `scopeReady`（口径通过）与 `ready`（口径通过且两侧读数都已确认）——两者分开是因为「图上没读到」和「读数还没确认」需要不同的提示与不同的下一步）。界面在核对区底部新增「跨图核对」：选择或上传对照图（上传走同一套读取接口）、两侧主张选择器、四要素并排表格、逐要素「确认一致」、对照图读数确认（走 `/api/audit/check`，与当前图同一套确定性规则）、更换与移除对照图。

对照图有独立的观察值、确认状态、结论与记录，移除或替换它都不影响当前图；当前图换图时清掉配对确认但保留对照图。指标名对不上时不再默认选第一条主张，而是留空并提示手动选择或先核对指标口径。

实测（浏览器）：载入基准图后选「跨图对照：说法对不上」，四要素全部显示「一致」，闸门提示两侧读数未确认；确认对照图读数后显示其图内结论「图内一致」，确认当前图读数后闸门变为「可以比较」；换成「范围不同」那张时范围显示「不一致」且提示「还差 范围／人群……保持『待核对』」，点「确认一致」后状态变为「你已确认一致」；更换对照图会重新挑选候选主张并清空逐项确认。1707px 与 320px 无横向溢出。

测试：`npm test` 65/65 通过（新增 7 条口径比对用例，覆盖归一化、候选挑选、四要素三种走向、按观察点分别比对时间与单位、未确认不参与比较）；`npm run test:e2e` 6/6；`npm run typecheck`、`npm run build` 通过。跨图数值结论与证据展示属于任务 03，本任务的闸门目前只到「可以比较」。

**两轴代码审查后的修正（同日）：**①「确认一致」原先对「不一致」也生效，等于让读者把「全国门店 vs 直营门店」点一下抹平，与规格「用户确认只用于补上图上读不到的信息」和 `expectations.json` 里「范围不同必须停在待核对」冲突；现已只对「图上没读到」提供该按钮，不一致的要素不给按钮、也不接受覆盖（单测固定）。②重置审计原先不清跨图层；现在重置会连同对照图、逐项确认与手填轴起点一起清空，符合规格的会话范围。③删掉三处死代码（`axisOf`、`crossSideClaims`、`referenceClaim`），把展示换算抽到 `web/cross-image-view.ts` 并补了单测；`CrossImageVerdict.status` 复用 `AuditStatus`，`formatNumber`／`formatPercent` 统一从 `shared/audit.ts` 引入；对照图的 blob URL 在替换时回收。
