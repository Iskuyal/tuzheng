# 04：柱状图纵轴风险与从零起点对照视图

**What to build:** 柱状图纵轴不从零开始时提示「可能误读」，并用已确认数值重画从零起点的对照图。

**Blocked by:** 01

**Status:** completed

- [x] 轴最小值 > 0 且两个数值都可读时显示「可能误读」，并给出原图轴范围与从零起点的高度比。
- [x] 轴信息缺失时显示「需要确认轴范围」，用户可手填轴最小值后重新判断。
- [x] 对照视图用已确认数值与轴起点确定性重画两根柱子，原图轴范围与从零起点两版并排；不调用模型。
- [x] 文案明确「可能误读」是呈现方式风险，不是造假判断；从零起点差异不大时也要如实说明。
- [x] 自动化测试覆盖风险规则、轴缺失降级、高度比计算与对照视图的渲染数据。

## Comments

**2026-09-26 实现与实测：**新增 `shared/axis-risk.ts` 的 `assessAxisRisk(axis, values, overrideMin)`：轴起点读不到时返回「需要确认轴范围」，起点 ≤ 0 返回「从零起点差异不大」，起点 > 0 返回「可能误读」并给出原图轴范围下的柱高（较矮的一根可能为 0）、从零起点的柱高与比值、以及「这是呈现方式的风险提示，不能据此认定作者造假」的原因行。用户手填的最小值优先于图上读数（先填后判的优先级在测试里固定下来）。

界面在核对区新增「纵轴核对」：状态胶囊、结论文字、两版柱形并排（原图轴范围 / 从零起点，高度按各自范围归一化并给出数值标注）、需要确认时提供「纵轴最小值」输入与「按这个起点重新判断」，以及边界说明（对照图按已确认读数重画，不经过模型）。换图时清空手填的起点。

实测（浏览器）：`axis-truncated` 显示「可能误读」，两版柱形是 0/20 与 80/100，文字说明较矮那根「完全贴住基线、看不出高度」且实际差异只有 25%；`axis-zero-based` 显示「从零起点差异不大」；`axis-unknown-start` 显示「需要确认轴范围」并给出输入框，手填 80 后重新判断变为「可能误读」且轴范围标注更新为起点 80；1707px 与 320px 无横向溢出。

测试：`npm test` 73/73 通过（新增 4 条纵轴规则用例：从零起点、截断、刻度读不清降级、手填最小值后重判、无轴信息给出比值）；`npm run test:e2e`、`npm run typecheck`、`npm run build` 通过。跨图与纵轴路径的窄屏自动化属于任务 05。
